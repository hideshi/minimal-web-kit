# ドキュメントの案内

今の仕様と手順は、`plans/` と `experiments/` を除くこの階層が正本です。`plans/` は、決めた経緯の記録です。

| 場所 | 内容 |
|---|---|
| [data-inventory.md](data-inventory.md) | 取得・保存データの台帳（`test/data_schema_test.go` が照合する） |
| [components.md](components.md) | 共通部品、画面の型、用語とメッセージ |
| [ui-guidelines.md](ui-guidelines.md) | 動きのあるUIの作り方 |
| [richtext.md](richtext.md) | 本文の記法の仕様 |
| [deploy.md](deploy.md) | 本番デプロイの手順例 |
| [ui/use-cases.md](ui/use-cases.md) | 誰が何を達成するために使うか（`test/usecase_test.go` が照合する） |
| [domain/](domain/) | 機能ごとの用語・状態・不変条件・権限（`test/domain_test.go` が照合する） |
| [plans/](plans/) | 機能の計画書、棚卸し、比較の記録 |
| [experiments/](experiments/) | 方式の検証の試作と結果 |

`domain/` の不変条件の表は、「条件」の列が守るべき要件で、「守る場所」「実装・検証」の列が実装との対応です。条件を関数名やSQLで言い換えず、実装が変わっても条件が変わらなければ、対応の列だけを直します。

## 正本と実装が食い違ったとき

どちらかに自動で合わせません。不具合ならコードを直し、要件が変わったのなら正本を直します。どちらか分からなければ、利用者か保守者に確かめます。`test/domain_test.go` と `test/usecase_test.go` が見るのは番号の対応だけで、内容の一致はレビューで確かめます。

## 変更の大きさと文書

| 変更 | 文書 |
|---|---|
| 誤字、挙動の変わらないリファクタリング | 更新しない |
| 既存の要件に戻す修正 | 関連する要件と回帰テストを確かめる。正本が正しければ更新しない |
| 目的・判断・状態・権限・保持・公開の約束を変える | 実装の前に正本を更新する。計画書と図は、複雑なときだけ作る |
| `AGENTS.md` の承認が要る5項目に触れる | 小さくても承認を取る |

## 計画書

新しい計画書は `plans/` に置きます。計画書は、1回の変更の進め方と決定の記録で、今の仕様ではありません。決定を今の仕様として読まないでください。

- 冒頭に、状態、対象の時点、正本へのリンクを書く。
- 完了するときに、続いていく決定を正本へ移す。採らなかった案と、その時だけの判断は計画書に残す。
- 完了後は本文を書き換えない。更新してよいのは、冒頭の状態と、後の計画への案内だけ。
