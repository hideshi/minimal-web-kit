# ユースケース一覧

誰が何を達成するために機能を使うかの正本です。操作の可否・状態・条件は `docs/domain/`、保存項目は `docs/data-inventory.md` を見ます。ここには書き写しません。

キットの同梱機能でできることを書きます。実際の利用者像と業務の判断（誰が何を見て公開を決めるか等）は、キットから作るアプリの側で書きます。

書き方の詳細は、後ろの「書き方」を見ます。今はカタログだけを試行しています。

## アクター

| アクター | 説明 |
|---|---|
| 閲覧者 | サイトを見る人。ログインせず、Cookieも持たない |
| 管理画面の利用者 | 管理画面にログインする人。カタログでは管理者とメンバーの権限は同じ |

## カタログ（[仕様](../domain/catalog.md)）

| ID | アクター | ユースケース | 入力情報（何を見るか） | 判断（何を決めるか） | 関連 |
|---|---|---|---|---|---|
| UC-CATALOG-1 | 閲覧者 | 目的の項目を探す | 公開項目の一覧、キーワード、カテゴリ、タグ | どの項目を開くか | 項目、カテゴリ、タグ |
| UC-CATALOG-2 | 閲覧者 | 項目の内容を読む | 公開項目の本文 | - | 項目 |
| UC-CATALOG-3 | 管理画面の利用者 | 項目を下書きとして用意し、内容を整える | 作成・編集の画面 | - | 項目、カテゴリ、タグ |
| UC-CATALOG-4 | 管理画面の利用者 | 用意した項目を公開する | 編集の画面の内容 | 公開してよいか | 項目 |
| UC-CATALOG-5 | 管理画面の利用者 | 公開をやめる | 一覧の公開状態 | 下書きに戻すか、削除するか | 項目 |
| UC-CATALOG-6 | 管理画面の利用者 | 不要な項目を削除する | 削除の確認画面の項目名 | 元に戻せなくてよいか | 項目 |
| UC-CATALOG-7 | 管理画面の利用者 | カテゴリとタグを整える | 分類の一覧の使用件数 | 名前を変えるか、削除するか | カテゴリ、タグ |

## 書き方

- 1行は利用者の目的の単位にする。「保存」「確認」のようなボタンの単位に分けない。
- 関連には `docs/domain/` の用語を書く。
- 入力情報と判断は、人の判断が要る行にだけ書く。無ければ `-` にする。
- IDは `UC-機能名-番号` で、使い回さない。やめた目的は表から消して、番号を欠番にする。
- 目的を達成できることを確かめるテスト関数の説明コメントに、`// ユースケース: UC-CATALOG-1` の形でIDを書く。`test/usecase_test.go` が、IDの重複・テストの無いID・表に無いIDの参照を検出する。IDが書いてあることは、目的を達成できる証明ではない。内容はレビューで確かめる。
- 目的・アクター・判断が変わる変更では、実装と同じコミットで更新する。コードから推定した目的は、利用者か保守者が確かめる。
- 画面設計書は作らない。標準の画面は `docs/components.md` の画面の型とテストに任せる。複数の役割が同じ画面を別の目的で使う、表示する情報が判断を左右する、分岐や復帰が複雑、標準の型から外れる、のどれかに当たる画面だけ、固有の内容を `docs/ui/screens/` に書く。
