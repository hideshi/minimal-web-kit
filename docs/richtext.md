# 本文の書き方（richtext）の仕様

固定ページ等の本文に使う、書き方を絞ったMarkdownの正本。キットのコード（`internal/web/richtext`）が、この規則で本文を**構造**（ブロックと文字の並び）に読み、`components.html` の部品が `html/template` で描く。HTMLの文字列は組み立てず、`template.HTML` は使わない。経緯は [pages-plan.md](plans/pages-plan.md) の3節。計画書と食い違うときは、この文書を正とする。

## 1. 前提と用語

- 本文は保存の前に `form.Text` を通す（CRLFをLFに揃え、改行・タブ以外の制御文字を拒否し、UTF-8を検証する）。読む処理はLFだけを前提にする。
- 「文字」は rune で数える。本文は5万文字まで。
- 読む処理は、同じ入力から同じ構造を返す純粋な関数 `Parse(body) (Doc, error)`。エラーは上限を超えたときだけで、書き方の誤りはエラーにせず、文字として出す。
- `ParseWithImages(body)` は、順5.5の画像の行も読む。固定ページの保存の検査・公開の表示・プレビューが使う。社内文書は `Parse` のままで、同じ行は段落の行になる。読み方の違いはこの行の種類だけ。
- `ParseForPages(body)` は、`ParseWithImages` に加えて、2.2節のLPの部品の行（順5.6〜5.8）も読む。固定ページの保存の検査・公開の表示・プレビューは、`ParseWithImages` の代わりにこれを使う。社内文書の `Parse` は、この行を段落の行として読む。経緯は [lp-plan.md](plans/lp-plan.md)。
- **空白**: `unicode.IsSpace` に当たる文字（半角スペース・タブ・全角スペース等）。ただし、記号の後ろの区切り（`## `・`- `・`1. `・`表: ` の空白）は**半角スペース1つだけ**を指す。
- **行の整え方**: 各行の末尾の空白は、判定の前に取り除く（出力にも残らない）。行頭の空白は残す。

## 2. 行の種類を決める順番

本文を行に分け、上から1行ずつ、**整えた生の行のまま**（`\` を解決する前に）種類を決める。「次の行」「その次の行」も整えた行で見る。

| 順 | 条件 | 種類 | 今のブロック |
|---|---|---|---|
| 1 | 空行（整えた後に何も無い） | — | 閉じる |
| 2 | `## ` か `### ` で始まり、その後に1文字以上ある | 見出し（h2・h3） | 閉じる |
| 3 | `表: ` で始まり、その後に1文字以上あり、**次の行が `\|` で始まり、その次の行が次の行に対する区切り行**（2行先読み） | 表の説明 | 閉じる |
| 4 | `\|` で始まり、次の行がこの行に対する区切り行（3節） | 表の見出しの行 | 閉じる |
| 5 | 表の途中で、`\|` で始まる | 表の行 | 続く |
| 5.5 | `ParseWithImages` で、行全体が2.1節の形 | 画像 | 閉じる |
| 5.6 | `ParseForPages` で、本文の最初の空でない行が2.2節のヒーローの行の形 | ヒーローの導入 | 閉じる（開いたブロックは無い） |
| 5.7 | `ParseForPages` で、行が2.2節のボタンの行の形 | ボタン | 直前のブロックがヒーローかボタンの並びで、ボタンが3つ未満なら続く。それ以外は閉じて、新しいボタンの並びを始める |
| 5.8 | `ParseForPages` で、行が2.2節のカードの行の形 | カード | 直前のブロックがカードの並びで、カードが12枚未満なら続く。それ以外は閉じて、新しいカードの並びを始める |
| 6 | `- ` で始まり、その後に1文字以上ある | 箇条書きの項目 | 箇条書きでなければ閉じる |
| 7 | 半角数字（`0`〜`9`）1〜9桁＋`. ` で始まり、その後に1文字以上ある | 番号付きの項目 | 番号付きでなければ閉じる |
| 8 | それ以外 | 段落の行 | 段落でなければ閉じる |

- 段落の途中でも、順2〜7に当たる行は新しいブロックを始める。
- 行頭に空白がある行（`  - x`・`\t- x`・`　- x`）、`#`・`####` 以上・`##` だけ・`##　x`（全角スペース）・`-\tx`・`０. x`（全角数字）は、段落の行。
- 番号付きの数字の値は使わない（`ol` の順で出す）。先頭の `0` も許す。
- 項目は1行だけ。項目の次の行が同じ種類でなければ、リストを閉じる（項目の折り返しは書けない）。
- 段落の行は、ブロックの中で改行（`br`）でつなぐ。
- 見出し・項目の文字は、記号の後ろの前後の空白を除く（`##  x` は「x」）。表の説明と同じ扱い。
- 区切り行の形の行が表の見出しの行として判定されなかった場合（例: 表の途中、列の数が違う）は、順5や順8でそのまま読む。

### 2.1 画像の行

判定は3.1節の走査の結果の記号で行う。`!` は記号でも `\` で作れる文字でもない。

1. 行の先頭が `![`（行頭に空白が無い）。2文字目は記号の `[`。
2. 次の記号の `]` までが説明。その間の `[`・`(`・`)`・`|`・`*` の記号は文字として扱い、強調やリンクは読まない。
3. `]` の直後が記号の `(`。
4. 次のトークンから行末の記号の `)` の手前までがURL。記号も `\` で作った文字も含まない。
5. URLが `/media/` に、ファイル名 `^[a-f0-9]{32}\.(jpg|png)$` を続けた形。
6. 説明は、`\` を解決し、前後の空白を除いた後で1〜200文字。その文字を説明に使う。リンクの文字と違い、前後の空白を除く。

どれかに当たらなければ、段落の行として読む。

- ブロックが持つのは説明とファイル名で、URLは持たない。公開ページとプレビューで、描く側が組み立てる。
- 画像は本文に100個まで。超えたら上限のエラーを返す。読む時間は行の長さに比例する。
- 挿入のボタンは `ImageLine` で行を作る。読みを変える `\` と `]` だけを `\` で逃がす。

### 2.2 LPの部品の行

`ParseForPages` だけで読む。前置きは `表: ` と同じく、日本語の名前・半角のコロン・半角スペース1つ。行は1節の整え方（末尾の空白を除く）の後で見る。どれかに当たらなければ、段落の行（順8）。入力の文字は落とさない。

| 行 | 形 |
|---|---|
| ヒーロー | `ヒーロー: ` で始まり、**本文の最初の空でない行**である。前置きの後ろを3.1節の走査と4節で読み、`\` を解決した後の文字に空白以外の文字が1つ以上ある。文字の並び（強調・リンク）は段落と同じ |
| ボタン | `ボタン: ` で始まり、前置きの後ろを3.1節の走査と4節で読んだ並びが、前後の空白（`unicode.IsSpace`）の文字を除いた後で、**リンクちょうど1つ**だけ（前後に空白以外の文字も強調も無い） |
| カード | `カード: ` で始まり、前置きの後ろを3.1節の走査で読んだ並びに、**記号の `\|` がちょうど1つ**ある。その前が題名、後ろが説明。どちらも4節で読み、前後の空白を除き、`\` を解決した後の文字に空白以外の文字が1つ以上ある |

- ヒーローは本文に1つだけ。最初の空でない行でない `ヒーロー: ` の行は段落の行。
- ヒーローの直後の（空行をはさまない）ボタンの行は、ヒーローのボタンになる（3つまで）。
- 空行は、ボタンとカードの並びを閉じる。
- 上限（ボタン3つ・カード12枚）を超えた行は、捨てずに新しい並びの最初になる。
- カードの区切りの `|` は記号の `|` だけ。`\|` は文字。リンクのURLの中の `|` も記号として数えるので、`|` を含むURLはカードの中で使えない（5節のとおり、URLは `\` で作った文字を許さない）。
- `ヒーロー\:`・`ボタン\:`・`カード\:` と書くと、前置きに当たらず段落の行になり、`\:` は `:` の文字になる（`表\:` と同じ）。
- 速さ: 判定は1行ずつ、直前のブロックの種類と並びの数だけを見る。後ろへの探索は足さない。読む時間は入力の長さに比例する。

#### 描き方

| ブロック | HTML |
|---|---|
| ヒーロー | `section.hero` の中に、ページの題名の `h1.hero-title`、導入の `p.hero-lead`、ボタンがあれば `div.hero-cta`。ヒーローのあるページは、通常の題名の `h1` を出さない |
| ボタンの並び | `a.btn` の並び。最初が `btn-primary`、2つ目から `btn-secondary`。本文のリンクと同じく同じタブで開く |
| カードの並び | 3枚か6枚なら `div.grid-3`、それ以外は `div.grid-2`。各カードは `article.card` に、題名の見出しと `p.card-content`。題名の見出しは、その並びより前に本文の `## ` の見出しが1つでもあれば `h3`、無ければ `h2`（カードの題名が作った `h2` は数えない） |

## 3. 表

### 3.1 行を記号の並びに分ける（4節と同じ走査）

表の行も、見出し・段落・項目の文字も、**同じ1回の走査**で読む。左から1文字ずつ読み、`\` の次が `\ * [ ] ( ) | # - . :` の11文字のどれかなら、2文字を組にして「その文字」として消費する（`\\` は `\` 1文字、`\|` は文字の `|`）。それ以外の文字の前の `\`（`\a`・`\1`・`\表`）と、行末の `\` は、`\` の文字として残す。組にならなかった `|`・`*`・`[`・`]`・`(`・`)` が記号になる。

- **列の分け方**: 記号の `|` で分ける。先頭と末尾の記号の `|` は外す。各セルの前後の空白を除く。例: `| a \\| b |` → 2セル「a \」「b」。`| a\|b | c |` → 2セル「a|b」「c」。`||` → 空のセル1つ。
- **区切り行**: 行を同じ方法で分けた各セル（前後の空白を除く）が、`\` で作った文字を含まず、`:` を前後に0〜1個付けた `-` 3個以上（`---`・`:---`・`---:`・`:---:`）で、セルの数が**見出しの行のセル数と同じ**。並びの指定（`:`）は使わない。
- 列の数は見出しの行で決まる。データ行のセルが少なければ空のセルで埋める。**多ければ `Parse` がエラー**を返す（入力を黙って捨てない）。
- 表は、`|` で始まる行が続く間続く。
- **説明（caption）**: 表の説明の行の `表: ` の後ろを、`\` を解決した文字として使う（強調・リンクは読まない）。説明が無ければ「表N（直前の見出し）」、見出しが無ければ「表N」。Nは本文の中の表の順（1から）。直前の見出しは、その表より前で最後に出た見出しの、強調・リンクの記号を除いた文字。
- 上限: 見出しの行が20列まで、データ行が200行まで。超えたら `Parse` がエラーを返す。
- 見出しの行のセルは `th scope="col"`、それ以外は `td`。

## 4. 文字の並び（見出し・段落の行・項目・セルの中）

3.1の走査で作った「文字と記号の並び」を、左から読む。

| 書き方 | 出力 | 規則 |
|---|---|---|
| `**文字**` | 強調 | 記号の `*` が2つ続いた所から、次の記号の `**` までが中身。中身が空か空白だけ、または閉じる `**` が無ければ、開きの `**` は文字にして、その後ろから読み続ける。中身は文字だけ（記号も文字として出す。リンク・入れ子は扱わない） |
| `[文字](URL)` | リンク | 記号の `[` から、次の記号の `]` までが文字。その直後が記号の `(` で、次の記号の `)` までがURL。文字が空か空白だけ、`]` か `(` か `)` が無い、URLが5節の許可に当たらない、のどれかなら、`[` は文字にして、その後ろから読み続ける。文字の中は文字だけ（強調は扱わない） |
| それ以外の記号・文字 | 文字 | |

- 探索は、同じ並び（1行・1セル）の中だけ。
- **速さ（実装の要件）**: 読む前に、並びを右から左に1回走査して、各位置から「次の記号の `]`」「次の記号の `)`」「次の記号の `**`」の位置を表にしておく。すべての探索は表を引くだけにする。URLは2,048文字まで（超えたら `[` は文字）。これで読む時間は入力の長さに比例する。

## 5. リンクのURL

`\` を解決した後のURL（記号の `(` と `)` の間）を検査する。

| 種類 | 許可の条件 |
|---|---|
| 外部 | 文字どおり小文字の `https://` で始まる。`net/url` で解析でき、ホスト（`Hostname()`）が空でなく、`%` を含まず、ユーザー情報（`user@`）が無い |
| サイト内 | `/` で始まり、`//` と `/\` で始まらない |

- URLの中に `\` で作った文字（`\)` 等）があれば許可しない（URLの区切りを `\` でずらせないようにする）。
- どちらも、2,048文字以下で、空白・`\`・制御文字（`unicode.IsControl`。C0とC1）・書式文字（`unicode.Cf`。右から左への上書き等）を含まないこと。
- 許可しないURL（`http://`・`HTTPS://`・`mailto:`・`javascript:`・`data:`・`//example.com`・`/\example.com`・`https://`・`https:example.com`・`https://user@example.com` 等）は、`[文字](URL)` をそのまま文字として出す。
- リンクは同じタブで開く。

## 7. リンクだけを読む本文（お知らせ・カタログ）

お知らせとカタログの本文は、行の種類を決めない。空行で段落、段落の中の改行で行に分ける今の読み方（`form.Paragraphs`）のまま、**各行の中のリンクの記法だけ**を読む（`richtext.LinkLine`・`LinkParagraphs`）。経緯は [wordpress-import-plan.md](plans/wordpress-import-plan.md) の2節・10.3・13.1。

- 読むのは4節の `[文字](URL)` だけ。URLの許可は5節と同じ。強調（`**`）・見出し・リスト・表・画像は読まず、文字のまま出す。
- 3.1節の走査を、次の2つだけ変えて使う。
  - 記号は `[`・`]`・`(`・`)` の4つ（`|`・`*` は文字）。
  - `\` で逃がせるのは `\`・`[`・`]`・`(`・`)` の5文字。ほかの文字の前の `\` は文字のまま残る（`\*` は「\*」）。
- 読む時間は4節と同じ表引きで、行の長さに比例する。
- 説明文（検索結果・SNSのカード）は、リンクを読んだ後の文字から作る（`richtext.LinkPlain`）。リンクは文字だけが残る。
- APIとMCPが返す本文は、記法の文字のまま。
- **使わない所**: 匿名の訪問者が書いた本文（お問い合わせ）には使わない。訪問者が書いたリンクを管理者の画面で押せるようにしないため、部品 `paragraphs` のまま描く（`test/template_test.go` が確かめる）。
