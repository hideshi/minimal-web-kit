# ドメインモデル: 画像（features/media）

現在の仕様の正本。変更の経緯は [media-plan.md](../plans/media-plan.md)、本文の記法は [richtext.md](../richtext.md) の2.1節。

## 1. 用語

| 用語 | 英語名 | 意味 |
|---|---|---|
| 画像 | `Item` | 運営者が登録した1枚。縮小した本体、説明、大きさを持つ。ID は32文字の乱数で、登録した人は保存しない |
| ファイル名 | `File` | `<id>.<形式>`（例: `0123….jpg`）。形式は `jpg`・`png` |
| 説明 | `Alt` | 画像が見えない人への文（代替テキスト）。必須で1〜200文字の1行。固定ページの本文では、本文に書いた説明を使う |
| 参照 | `Ref` | どの記事がどの画像を使うかの記録。記事の保存と一緒に更新する |
| 所有する機能 | `MediaOwner` | 画像を使う機能（固定ページ、お知らせ、カタログ） |
| 代表画像 | `Cover` | お知らせ・カタログの記事が持つ1枚。固定ページは本文に画像を書く |

## 2. 概念と関係

画像は記事とは別に管理し、1枚を複数の記事で使える。匿名OwnerIDの所有物ではない。

## 3. 状態の移り変わり

画像に公開状態は無く、状態の遷移は無い。公開ページに出るかは、参照と記事の状態から毎回判定する。

| 画像が使われている先 | `/media/...` | 管理者の経路 |
|---|---|---|
| どの記事からも使われていない | 404 | 見える |
| 下書きの記事だけ | 404 | 見える |
| 公開予約で、公開日時の前のお知らせだけ | 404 | 見える |
| 外した機能の記事だけ | 404 | 見える |
| 公開中の記事が1つ以上 | 200 | 見える |

記事を公開すると、同時に画像も公開される。画像への操作は要らない。

## 4. 不変条件

| 番号 | 条件 | 守る場所 |
|---|---|---|
| MEDIA-INV-1 | 公開の経路で見えるのは、公開中の記事が今使っている画像だけ。判定は記事の公開ページと同じ条件（予約公開の日時を含む）で毎回行い、記事の状態と使っている画像を1回の読み取りで確かめる。参照の記録が古くても公開しない。それ以外は無い画像と同じ404にする | `isPublic`・各機能の `MediaIsPublic` |
| MEDIA-INV-2 | 公開の経路はCookieを発行・照合しない。URLは正規の1つの形だけを認める。200はサーバーが決めた形式で1日キャッシュでき、404はキャッシュさせない | `handlePublic`、独立経路 |
| MEDIA-INV-3 | 受け取るのは中身がJPEG・PNGの画像だけ。大きさと画素数の上限はデコードの前に確かめる。保存するのは再エンコードした画像だけで、EXIF（撮影位置）・元のファイル・元のファイル名を残さない。向きは画素に適用する | `process`・`inspect` |
| MEDIA-INV-4 | 追加・編集・削除・管理者の経路はサイトを管理するロールだけ。変更はPOSTで同一オリジンとCSRFを確かめ、multipartはファイルを読む前にCSRFを確かめる。本文の上限が広いのは追加の経路だけ | `Admin.Upload`・`guard.UploadToken`・`HandleUpload` |
| MEDIA-INV-5 | 参照の更新は、記事の保存・削除と同じトランザクションで行い、失敗すれば記事も戻る。無い画像は参照できない。使われている画像は削除できない（DBの外部キーでも止める） | `ReplaceRefs`・各機能の保存、`Store.Delete` |
| MEDIA-INV-6 | 画像の合計は、同時の送信でも全体の上限を超えない | `Store.Add` |
| MEDIA-INV-7 | 起動時に、待ち受けの前に有効な機能の参照を作り直す。外した機能の参照は残し、公開中として数えず、削除を止める | `Startup`・`Rebuild` |
| MEDIA-INV-8 | 本文の参照は、表示と同じ読み方の画像のブロックだけから取り出す。社内文書は画像を読まない | `ParseWithImages`・`Doc.Images` |
| MEDIA-INV-9 | 代表画像は、選択の一覧の範囲の外でも画面に出し、本文だけの保存で消えない。MCPの更新は代表画像を変えず、確認の後に代表画像が変わったら保存しない | `CoverChoices`、各機能の `*IfUnchanged` |
| MEDIA-INV-10 | ファイル名・説明・画像のIDをログに出さない | `web.RequestIDAttr`（ログには要求の番号だけを出す） |
| MEDIA-INV-11 | 画像機能が無い構成でも、各機能は記事を保存・表示できる。本文の画像の行は説明の文字として描き、代表画像の値は変えない | `features.NoMedia` |

## 5. 加工

| 項目 | 内容 |
|---|---|
| 入力 | JPEG・PNG、8,000,000バイトまで。SVG・GIF・WebP・HEICは断る |
| 画素数 | 通常のJPEGと8ビットのPNGは2,400万画素、プログレッシブ・CMYKのJPEGと16ビットのPNGは1,200万画素、1辺12,000pxまで |
| 形式の判定 | JPEGは画像の本体の手前まで部品を全部読み、フレームの見出しが見つからないものは断る |
| 同時処理 | 加工は1件まで。空くのを10秒待ち、空かなければ503と `Retry-After`。本文の受信は枠の外で行う |
| 縮小 | 長辺1,600pxまで（Lanczos3）。拡大はしない |
| 形式 | 写真はJPEG（品質80）。PNGは、透明があればPNGのまま、透明が無ければ小さいほうの形式 |
| 色 | 色プロファイルを扱わない。P3色域の写真は色が少し薄く見えることがある |

測定は [画像の加工の測定](../experiments/media-image-processing.md)。

## 6. 権限

| 操作 | システム管理者 | サイト管理者 | 一般ユーザー | 未ログイン |
|---|---|---|---|---|
| 公開中の画像の閲覧 | 可 | 可 | 可 | 可 |
| 追加・説明の編集・削除・下書きの画像の閲覧 | 可 | 可 | 不可 | 不可 |

## 7. 他の機能との関係

- 管理者認証（`features/auth`）か共通認証（`features/federatedauth`）の `features.Admin` の口を使う。ファイルの送信は `Upload` で受ける。
- 各機能は `features.Media` の口だけを使い、`media_*` の表を読まない。`media` は各機能の表を読まず、`features.MediaOwner` で問い合わせる。
- 参照の更新は、各機能が持つ接続を受け取って行い、`media` はトランザクションを始めない。
- MCPの第1段階では、固定ページの本文に既存の画像の記法を書ける。アップロードと代表画像の変更は扱わない。
- 公開の画像はCDNでキャッシュできる。公開を取り消しても、CDNとブラウザに残った分は最長1日表示され得る。

## 8. 守らない範囲

- 動画、画像以外の添付、閲覧者や一般ユーザーの投稿、画像の編集、外部のオブジェクトストレージ、SVG、大きさ違いの複製（`srcset`）、`og:image`、JSON APIの画像の項目。
- MCPからのアップロード、公開の取り消しのCDNの消去。
- 写真の掲載の許可の判断、顔や名札の検出。運営者の責任で確かめる。
- 色の管理（P3からsRGBへの変換）。
- 静的書き出し（画像機能を有効にすると `export-static` は使えない）。
- DBファイルの大きさの上限。全体の上限は画像の合計で、監視は `docs/deploy.md` の8節を見る。
