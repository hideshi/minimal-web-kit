# ドメインモデル: 管理者認証（features/auth）

管理者認証の今の仕様の正本です。用語・概念・状態・不変条件・権限をここにまとめます。変更の経緯は `docs/plans/auth-plan.md`（計画書）、保存する列の詳細は `docs/data-inventory.md` の4節にあります。

不変条件には番号（`AUTH-INV-n`）を振ります。番号は、それを確かめるテスト関数のコメントにも書きます。`test/domain_test.go` が、表の番号がすべてテストに書かれていること、コードに書かれた番号がすべて表にあることを確かめます。番号は使い回さず、廃止した条件は表から消して、番号を欠番にします。

## 1. 用語

| 用語 | 意味 |
|---|---|
| アカウント | 管理画面にログインできる単位。呼び名とロールを持つ |
| 呼び名 | アカウントを見分ける運用上のラベル（1〜50字・重複不可）。実名・メールアドレスを入れない運用とする |
| ロール | 管理者（`admin`）かメンバー（`member`） |
| 有効な管理者 | ロールが管理者で、停止中でなく、有効なパスキーを1件以上持つアカウント |
| パスキー | アカウントに登録した認証器の鍵（公開鍵と署名カウンタ）。既定では端末に固定された認証器だけを扱い、同期型は `AUTH_ALLOW_SYNCED_PASSKEYS=true` のときだけ扱う |
| 端末名 | パスキーを見分ける運用上のラベル（必須、1〜50字、前後の空白は除く、改行とタブは不可） |
| 管理者セッション | ログイン状態。Cookie `admin_session` の生トークンと、DBのハッシュで照合する |
| 登録トークン | パスキーを1つ登録するための1回限りの鍵。登録URLのフラグメントに入れて渡す |
| 登録URL | 登録トークンを含む `/admin/setup#token=...` |
| 複製の疑い | 署名カウンタが前回より進まなかったこと。認証器の複製を疑う |
| 連携先 | このアカウントでログインできる自社の別システム（`features/auth/oidcop` を登録した場合） |
| 利用許可 | アカウントに連携先の利用を認めること。連携先のロールとは別物 |
| 連携用の識別子（sub） | 連携先に渡す256ビットの乱数。パスキーのリセットでは変えない |
| 失効世代 | アカウント・連携先・利用許可の3つの整数。ログイン時に固定し、最新の値と一致する間だけ連携先のログインが有効 |

## 2. 概念と関係

```
アカウント 1 ─ n パスキー
アカウント 1 ─ n 管理者セッション
アカウント 1 ─ n 登録トークン（未使用は常に0か1）
```

- パスキー・管理者セッション・登録トークンは、必ずどれか1つのアカウントに属し、アカウントを削除すると一緒に消える。
- アカウントは匿名の所有者（OwnerID）とは無関係で、Coreのセッション破棄やGCでは消えない。
- WebAuthnの `user.id` はアカウントごとのランダム16バイト（`webauthn_user_id`）。鍵のリセットで作り直す。

## 3. 状態の移り変わり

アカウント:

```
未登録（パスキー0件）─ 登録URLでパスキーを登録 → 有効
有効 ─ 停止 → 停止中 ─ 再開 → 有効
未登録・有効・停止中 ─ 削除 → （消える）
有効 ─ 鍵のリセット（全パスキー削除）→ 未登録
```

パスキー: `有効 ─ 複製の疑い → 無効`。有効・無効とも削除できる（不変条件の範囲で）。自分のパスキーを削除すると、操作中のセッションを残して他のセッションを消す。管理者が他のアカウントのパスキーを削除すると、対象の全セッションを消す。

登録トークン: `未使用 ─ 登録 → 使用済み`、`未使用 ─ 期限・発行し直し → 無効`。使用済み・期限切れはGCで消す。

管理者セッション: `有効 ─ 無操作2時間・発行から12時間・ログアウト・取り消し → 失効`。

## 4. 不変条件

| 番号 | 条件 | 守る場所 |
|---|---|---|
| AUTH-INV-1 | 有効な管理者は常に1人以上いる。降格・停止・削除・鍵のリセットで0人になる操作は拒否する。例外は、最初の管理者の登録前、`auth-recover` の全体の復旧から登録し直すまで、複製の疑いによる無効化（安全を優先し、0人になったら `auth-recover` で戻す） | `effectiveAdminElsewhere` を条件に含む1つの文（`setRole`・`disableAccount`・`deleteAccount`・`reissueToken`） |
| AUTH-INV-2 | 自分自身のロール変更・停止・削除・鍵のリセットはできない（締め出しを防ぐ） | `changeAccount`、`handleReissueToken` |
| AUTH-INV-3 | パスキー・管理者セッション・登録トークンの読み書きは、アカウント単位で絞る。他のアカウントのものは「見つからない」扱いにする | `store.go` の各関数の `account_id` 条件 |
| AUTH-INV-4 | どのアカウントも、最後の有効なパスキーは削除できない（無効化済みは削除できる） | `deleteCredential` の1つの文 |
| AUTH-INV-5 | ロールと停止は要求ごとにアカウントから読む。停止中のアカウントは、残ったセッション・ログイン・登録URLのどれも使えない | `validateSession`・`login`・`checkSetupToken`・`registerWithSetupToken` |
| AUTH-INV-6 | ロール変更・停止・削除・鍵のリセットをしたら、そのアカウントの管理者セッションを同じトランザクションで消す | `changeAccount`・`resetAccountKeys` |
| AUTH-INV-7 | 登録トークンは1回限り・期限付き（`auth-setup`・`auth-recover` は15分、管理画面の発行は24時間）で、1つのアカウントに結びつく。発行し直すと、そのアカウントの未使用分だけが無効になる。消費とパスキーの保存は1つのトランザクションで行う | `issueSetupToken`・`registerWithSetupToken` |
| AUTH-INV-8 | 署名カウンタは単調に増える（両方0の認証器は除く）。後退したらそのパスキーを無効にし、そのアカウントの管理者セッションだけを消す。例外は並行ログインで、署名の検証の後に別のログインが先にカウンタを進めたときは、そのログインを拒否するだけで、パスキーとセッションは変えない | `login`・`disableCredential` |
| AUTH-INV-9 | 同期・バックアップできるパスキーは、`AUTH_ALLOW_SYNCED_PASSKEYS=true` のときだけ登録・ログインできる。既定は拒否。ログインのたびに判定するため、許可を外すと同期型ではログインできない。BE=0でBS=1のデータは設定に関係なく拒否する | `webauthn.go` のフラグ検査、`LoadConfig` |
| AUTH-INV-10 | ログインは、パスキーの持ち主のアカウントの `webauthn_user_id` と `userHandle` が一致するときだけ成功する | `handleLoginFinish` |
| AUTH-INV-11 | 管理者セッション・登録トークンの生の値はDBに保存しない（SHA-256のみ）。登録トークンはURLのフラグメントでだけ渡す | `hashToken`・`SetupURL` |
| AUTH-INV-12 | 管理者セッションは、無操作2時間または発行から12時間で失効する | `validateSession` |
| AUTH-INV-13 | ログには固定のイベント名とアカウント番号だけを出し、呼び名・端末名・トークン・credential IDは出さない | 各ハンドラのログ呼び出し |
| AUTH-INV-14 | ログイン中の状態を変える送信は、同一オリジンの確認とCSRFトークンの両方を通す。ログイン前の送信（ログイン、登録URLでの登録）は同一オリジンの確認を通し、登録は登録トークンも確かめる | `form`・`jsonEndpoint`・`guard` |
| AUTH-INV-15 | `auth-setup` は、有効なパスキーが1件も無いときだけ登録URLを出す | `Setup` |
| AUTH-INV-16 | `auth-recover`・`-reset-schema`・GCは管理者認証の表（連携の表を含む）だけに触れ、アカウント（`-reset-schema` を除く）と他の機能のデータは残す | `Recover`・`ResetSchema`・`Purge` |
| AUTH-INV-17 | 停止・削除・鍵のリセット・複製の疑い・復旧は、同じトランザクションでアカウントの失効世代を進め、固定済みの認可要求とコードを消す。連携先の停止・再開と、利用許可の取り消し・再付与も、それぞれの世代を進める。世代は戻さず、再開しても古いログインは復活しない。ロール変更と通常のログアウトは連携先のログインを失効させない | `migration.sql` のトリガー、`Recover`、`FederationStore` |
| AUTH-INV-18 | コードは一回限り・60秒で、連携先・戻り先・PKCEに結びつく。トークンの交換は、クライアント認証の後で、消費と応答の生成を1つのトランザクションで行い、コミットの後で応答を送る。認証済みの連携先が束縛の合う交換済みのコードを送ったときだけ利用許可の世代を進める。未認証の再送では何も変えない。PKCE S256はどの連携先にも必須 | `FederationStore.ConsumeCode`・`Atomic`、`oidcop` の `token`・`validAuthorizeQuery` |

前提: AUTH-INV-1・AUTH-INV-4・AUTH-INV-7・AUTH-INV-8 は、判定と更新を1つの文（またはトランザクション）で行い、同時操作でも破れないようにしています。これは、SQLiteが書き込みを1つずつしか通さないことに頼っています。DBを替えるときは見直してください。たとえばPostgreSQLの既定の分離レベル（READ COMMITTED）では、2人の管理者が同時にお互いを降格すると、どちらの文も相手を有効な管理者と数えて通り、有効な管理者が0人になりえます。その場合は `SERIALIZABLE` にするか、対象の行をロック（`SELECT ... FOR UPDATE`）してから判定します。

## 5. ロールと権限

| 操作 | 管理者 | メンバー |
|---|---|---|
| ログイン・ログアウト、自分のパスキーの追加・名前変更・削除 | ○ | ○ |
| 他の機能の `Page`・`Form` で守られた画面 | ○ | ○ |
| 他の機能の `AdminPage`・`AdminForm` で守られた画面 | ○ | × |
| アカウントの一覧・作成・ロール変更・停止・再開・削除・登録URLの発行、他のアカウントのパスキーの削除 | ○ | × |

管理者どうしは相互に信頼する前提です（管理者は他の管理者を降格・停止できる）。

## 6. 他の機能との関係

- 他の機能は `features.Admin` の口（`Page`・`Form`・`AdminPage`・`AdminForm`・`Layout`）だけを使い、管理者認証の表を直接読まない。
- `AdminSession` が渡すのは `AccountID`・`Role`・`IsAdmin` と画面用のデータで、呼び名は渡さない。
- `features/auth/oidcop` はこの機能を包み、連携の表は本体の `FederationStore` が扱う（停止との原子性のため）。本体からOIDCのライブラリはimportしない。
- 別のシステムが連携先になるときの約束は [共通認証の仕様](federatedauth.md) にある。
- 機能が `AccountID` を自分の表に保存する場合は承認境界2に当たる。`auth_accounts` へ外部キーは張らず、削除済みのIDは「削除済みのアカウント」として扱う。IDは再利用しない（AUTOINCREMENT）。

## 7. 守らない範囲

- 機能ごとの細かい権限、操作の記録（DBの監査ログ）、メールでの招待、他社のIDでのログイン、第三者への認証の開放。
- 管理者の権限を持つ人による悪用（管理者どうしは信頼する）。
- サーバーやDBファイルに直接触れられる人による改変。
- 同期型のパスキーを許可した場合の、同期の提供者（Googleアカウント等）の守り。複製は署名カウンタで検出できない。
- パスキーが同期型かどうかは保存しない。「有効なパスキー」（`AUTH-INV-1`・`AUTH-INV-15`）は `disabled_at` で数えるため、許可を外した後は、ログインできない同期型も数える。
