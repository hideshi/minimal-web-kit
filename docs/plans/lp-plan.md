状態: 2回目の計画のレビュー待ち（2026-11-06）。対象の時点は `615e4b2`。1回目のレビュー（Sol）の反映は11節。

## 1. 目的と範囲

1つの製品を、相手と切り口ごとに別のページ（LP）で説明し、資料・SNS・検索から直接その入口へ送れるようにする。新しい機能は作らず、固定ページ（`features/pages`）と本文の記法（`internal/web/richtext`）を広げ、ページごとのOGPの画像を自動で作る。

2026-11-06 に紹介サイトで、今の固定ページだけでLPを2つ作って公開した（`/lp-wordpress`・`/lp-content-flow`）。URL、見出し、箇条書き、番号つきの手順、表、リンク、狭い画面、Cookie無し、`title`・`description`・`canonical`・OGPの文字・`sitemap.xml` は今のままで足りた。足りなかった物と扱いは次のとおり。

| # | 足りない物 | 扱い |
|---|---|---|
| 1 | 行動を促すボタン（今は文字のリンクだけ） | 段階1。「ボタンの行」 |
| 2 | 最初の画面の力（題名が普通の見出し、導入が普通の段落） | 段階1。「ヒーローの行」 |
| 3 | 利点を横に並べるカード | 段階1。「カードの行」 |
| 4 | ページごとのOGPの画像（今はサイト共通の1枚） | 段階2。題名から自動で作る。本文に画像があれば最初の画像 |
| 5 | LPを書く人・AIがSEOと切り口を意識する手引き | 段階3。スキルを足す |
| 6 | どのLPから問い合わせが来たか | 範囲外。アクセス解析による流入の把握で足りるかを先に確かめ、個々の問い合わせへの紐付けは別の要件として決める（承認境界2） |

## 3. 本文の記法に足す行（段階1）

### 3.1 読み方の分け方

- 固定ページの本文は `ParseForPages`（仮。今の `ParseWithImages` の代わり。保存の検査・公開の表示・プレビュー・画像の参照の作り直し・公開の判定で同じ関数を使う）で読む。社内文書は `Parse` のままで、新しい行は全部段落の行になる。
- 前置きは `表: ` に揃え、日本語の名前・半角のコロン・半角スペース1つ。`ヒーロー\:`・`ボタン\:`・`カード\:` と書けば、今の `\:` の逃がしで、ただの文字（段落）になる。
- 判定は、今と同じく**整えた生の行**で行う。文字の並びの読み方（強調・リンク・逃がし）は、今の走査（`richtext.md` の3.1節・4節）を共有する。

### 3.2 判定の順番（`richtext.md` の2節の表に足す行。レビュー用の案）

| 順 | 条件 | 種類 | 今のブロック |
|---|---|---|---|
| 5.6 | `ParseForPages` で、**本文の最初の空でない行**が `ヒーロー: ` で始まり、その後に空白以外の文字が1つ以上ある | ヒーローの導入 | 閉じる（本文の最初なので、開いたブロックは無い） |
| 5.7 | `ParseForPages` で、`ボタン: ` で始まり、その後ろの文字の並びが**リンクちょうど1つ**（リンクの前後に文字も強調も無い） | ボタン | 直前がヒーローの導入かボタンの並びで、その並びが3つ未満なら続く。それ以外は閉じて、新しい並びを始める |
| 5.8 | `ParseForPages` で、`カード: ` で始まり、その後ろの文字の並びに**記号の `\|` がちょうど1つ**あり、その前（題名）と後（説明）がどちらも空白以外の文字を1つ以上持つ | カード | 直前がカードの並びで、その並びが12枚未満なら続く。それ以外は閉じて、新しい並びを始める |

- 最初の空でない行でない `ヒーロー: ` の行は、段落の行（順8）。ヒーローは本文に1つだけ。
- 条件に当たらない `ボタン: `・`カード: ` の行（リンクが2つ、リンクの前後に文字、`|` が0か2つ以上、題名か説明が空）は、段落の行（順8）。入力の文字は落とさない。
- 空行（順1）は、ボタンとカードの並びを閉じる。空行をはさんだボタンの行は、別の並びになる。ヒーローの導入の直後のボタンの行（空行をはさまない）は、ヒーローのボタンになる。
- 上限を超えた行は、捨てずに新しい並びを始める（4つ目のボタンは2つ目の並びの最初、13枚目のカードは2つ目の並びの最初）。
- カードの区切りの `|` は、3.1節の走査の記号の `|`。`\|` は文字。リンクのURLの中の `|` も記号として数えるので、`|` を含むURLはカードの中で使えない（URLは `\` で作った文字を許さない。`richtext.md` の5節）。
- 題名と説明の文字の並びは、見出しと同じ読み方（強調・リンク）。前後の空白を除く。

### 3.3 描き方

| ブロック | HTML | 備考 |
|---|---|---|
| ヒーロー | `section.hero` の中に、ページの題名の `h1.hero-title`、導入の `p.hero-lead`、ボタンがあれば `div.hero-cta` | ヒーローがあるページは、通常の題名の `h1` を出さない（`h1` は1つだけ）。無いページは今と同じ |
| ボタンの並び | `div`（クラスは実装で決める）の中に `a.btn`。並びの最初が `btn-primary`、2つ目から `btn-secondary` | リンクは今の本文のリンクと同じく**同じタブ**で開く（`richtext.md` の5節）。`target`・`rel` は付けない |
| カードの並び | 3枚か6枚なら `div.grid-3`、それ以外は `div.grid-2`。各カードは `article.card` に、題名の見出しと `p.card-content` | 題名の見出しは、**その並びより前に `h2`（`## `）が1つでもあれば `h3`、無ければ `h2`**。見出しの階層が飛ばない |

- `description` は、ヒーローがあればその導入から、無ければ今と同じく最初の段落から作る（120文字まで）。
- 管理画面のプレビュー・公開の表示・MCPの `pages_get` の本文は、同じ読み方で描く。

### 3.4 今の本文と移行の道具への影響

- `ヒーロー: `・`ボタン: `・`カード: ` で始まる行が既にある本文は、見え方が変わり得る。
  - 移行の道具（`cmd/wpimport/convert` の `escapeLineStart`）に3つの前置きを足し、`ヒーロー\:`・`ボタン\:`・`カード\:` に逃がす。HTML → 本文 → `ParseForPages` の回帰の試験で、元の段落のまま読めることを確かめる。
  - 起動の時に、固定ページの本文に新しい前置きで始まる行があるページを数え、ページのIDだけを警告のログに出す（本文は出さない）。数えるだけで何も変えない。
  - README の固定ページの節と、リリースの説明に、見え方が変わり得ることと、直し方（行頭を `ボタン\:` にする）を書く。
- 社内文書の本文の見え方は変わらない（`Parse` は新しい行を読まない）。

### 3.5 速さと試験

- 判定は1行ずつ、前の行の状態（直前のブロックの種類と並びの数）だけを見る。後ろへの探索は、今の表の判定（2行先読み）以外に足さない。読む時間は入力の長さに比例する。
- 試験: 3.2節の表の例を全部（境界: 上限の前後、空行、逃がし、`|` の数、リンクの数、最初の空でない行かどうか、先頭の空行）。社内文書の `Parse` で同じ本文が段落になること。
- 速さの試験: 長い1行（`ボタン: [[[…`、`カード: ||||…`）、多数の短い行（ボタンの行・カードの行を5万文字まで並べる）で、時間が入力の長さに比例すること。
- ファズ: 今の描画のファズ（`internal/web/richtext_fuzz_test.go`、`Parse` を通る）とは別に、`ParseForPages` と固定ページの描画を通るファズを足す。HTMLが崩れない、許可したタグ・属性・URLだけ、入力の文字を落とさない、を見る。許可のタグ・属性の一覧に `section`・`article`・クラスを足す。

## 4. OGPの画像（段階2）

### 4.1 決まり方

| 順 | 条件 | `og:image` |
|---|---|---|
| 1 | 公開中のページで、本文の画像のうち最初の1枚が画像の機能（`features.Media`）で公開用に解決できる | その画像（`/media/…`）。幅・高さ・説明は解決した値 |
| 2 | 1でなく、自動の画像を作れる（4.3節の文字が全部フォントにある） | 自動の画像 `/ogp/pages/{スラッグ}-{版}.png` |
| 3 | どちらでもない | 今と同じサイト共通の画像 |

- `og:image:width`・`height`・`alt`・`twitter:card` は、選んだ画像に合わせて一式を設定する。
- Site の `layoutData` は、今は `OGImagePath`・`OGImageAlt` を毎回上書きし、大きさは1200×630に固定している。**画面が設定済みの値は上書きしない**形に直し、大きさも値として渡す（今の `Description` と同じ扱い）。
- プレビュー（管理画面）では、OGPの画像を出さない。管理者用の画像のURLを `og:image` に出さない。
- 画像の機能が無い構成、画像の解決に失敗した時は、2へ進む。画像の表（`media_items`）を固定ページから直接読まない。

### 4.2 経路

- `GET /ogp/pages/{スラッグ}-{版}.png`（`IsolatedRoutesFeature`。Cookieを発行・照合しない。HEADも同じ）。固定ページの機能が持つ。
- `{版}` は、画像に描く文字（題名とサイト名）と、描き方の版の番号から作るハッシュの先頭12文字。題名を変えると版が変わり、古いURLは404になる。
- 返すのは、**今公開中**（予約の時刻を過ぎている）のページで、版が今の題名と一致する時だけ。それ以外（下書き、予約の前、非公開、無いページ、版の違い、4.3節の文字が足りない）は、Siteの404。
- 応答は `Content-Type: image/png`、`Cache-Control: public, max-age=31536000, immutable`（版がURLに入るので変わらない）。非公開に戻した後も、Cloudflare 等に残った画像は期限まで配られ得る（守らない範囲。今の `/media/` と同じ扱い）。
- 同時に作る数は2つまで（超えたら待たずに503）。作るのは1枚10〜20ms（試作）。保存はしない。

### 4.3 描き方

- 1200×630。背景、上端の帯、題名（最大3行）、下にサイト名（`SITE_NAME` 等、今のレイアウトが使う名前）。色はキットの既定の色で固定する（テーマ `theme.css` の色は使わない。11節の決めること）。
- フォント: Noto Sans CJK JP Bold を、JIS X 0208 の文字（第1・第2水準・記号・かな）と ASCII に絞ったもの（約1.5MB、OFL 1.1）。`internal/web/ogimage/` に置き、ライセンスの全文を同じ場所に置く。絞り方のスクリプト（fontTools を使う。開発の時だけ）も残す。
- 題名に**フォントに無い文字が1つでもあれば、自動の画像は作らない**（4.1節の3へ）。豆腐（□）を出さない。
- 折り返し: 幅で折り返す。行頭に来てはいけない文字（`、。，．）」』】！？ー` と小さいかな等）は前の行に残す。最後の行が2文字以下にならないよう、行を均す。4行目以降は出さず、3行目の末尾を `…` にする。
- 部品は Core（`internal/web/ogimage`）に置き、お知らせ・カタログに広げる時にも使えるようにする（この計画では固定ページだけ）。

### 4.4 試験

- 決まり方: 画像あり（公開中の記事で共有・非公開・解決失敗）、画像の機能が無い構成、フォントに無い文字、Siteが無い構成。
- 経路: 公開中・下書き・予約の前と後・非公開に戻した後・無いページ・版の違い・HEAD・Cookieが付かないこと・`Cache-Control`。同時の上限の503。
- 描画: 同じ入力で同じバイト列になること（版のハッシュを信じてよいことの確かめ）。行頭の禁則と行の均し、3行の切り詰めの境界。
- 依存: `test/architecture_test.go` の許可の一覧に `golang.org/x/image` を足し、サーバーに組み込まれる部品の一覧も直す。フォントのライセンスの全文があることを試験で見る。

## 5. LPとSEOのスキル（段階3）

`skills/minimal-web-kit-lp/SKILL.md`（150行以内）を足す。規約は `minimal-web-kit-design` 等を参照し、写さない。

1. 切り口を1ページに1つに絞る（相手、困りごと、言葉）。営業資料や社内の文書から起こす時は、資料に無い主張を足さない。

5. 同じ製品のLP同士で、文が重なりすぎないようにする（`canonical` は各ページ自身）。
6. OGPの画像: 何もしなければ題名から作られる。写真を使うなら、横長の画像を本文の最初の画像にする（ヒーローの後でよい）。

8. 約束しないこと: 順位、問い合わせの増加、未検証の数字（`minimal-web-kit-design` の5節）。
9. MCPで下書きを作り、人が確かめて公開する（AIが無断で公開しない）。
