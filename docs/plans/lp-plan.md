# 切り口ごとのLP 実装計画

状態: 段階1を実装中（2026-11-06）。対象の時点は `615e4b2`。計画のレビュー（Sol）の反映は11節（1回目）と12節（2回目）。読み方の表のレビュー（Sol、3回目）は高・中なしで、低の2件（境界の例）を `richtext.md` に足した。

## 1. 目的と範囲

1つの製品を、相手と切り口ごとに別のページ（LP）で説明し、資料・SNS・検索から直接その入口へ送れるようにする。新しい機能は作らず、固定ページ（`features/pages`）と本文の記法（`internal/web/richtext`）を広げ、ページごとのOGPの画像を自動で作る。

2026-11-06 に紹介サイトで、今の固定ページだけでLPを2つ作って公開した（`/lp-wordpress`・`/lp-content-flow`）。URL、見出し、箇条書き、番号つきの手順、表、リンク、狭い画面、Cookie無し、`title`・`description`・`canonical`・OGPの文字・`sitemap.xml` は今のままで足りた。足りなかった物と扱いは次のとおり。

| # | 足りない物 | 扱い |
|---|---|---|
| 1 | 行動を促すボタン（今は文字のリンクだけ） | 段階1。「ボタンの行」 |
| 2 | 最初の画面の力（題名が普通の見出し、導入が普通の段落） | 段階1。「ヒーローの行」 |
| 3 | 利点を横に並べるカード | 段階1。「カードの行」 |
| 4 | ページごとのOGPの画像（今はサイト共通の1枚） | 段階2。題名から自動で作る。本文に画像があれば最初の画像 |
| 5 | LPを書く人・AIがSEOと切り口を意識する手引き | 段階3。スキルを足す |
| 6 | どのLPから問い合わせが来たか | 範囲外。アクセス解析による流入の把握で足りるかを先に確かめ、個々の問い合わせへの紐付けは別の要件として決める（承認境界2） |
| 7 | 構造化データ（JSON-LD） | 範囲外。`<script>` をテンプレートに書かない決まりとCSPの関係を別に調べる |

作らない物: 自由なHTML・CSSの欄、ページごとのレイアウトの選択、A/Bテスト、フォームの項目の自由な作成、LP専用の機能・表・管理画面、OGPの画像を選ぶ欄。

## 3. 本文の記法に足す行（段階1）

### 3.1 読み方の分け方

- 固定ページの本文は `ParseForPages`（仮。今の `ParseWithImages` の代わり。保存の検査・公開の表示・プレビュー・画像の参照の作り直し・公開の判定で同じ関数を使う）で読む。社内文書は `Parse` のままで、新しい行は全部段落の行になる。
- 前置きは `表: ` に揃え、日本語の名前・半角のコロン・半角スペース1つ。`ヒーロー\:`・`ボタン\:`・`カード\:` と書けば、今の `\:` の逃がしで、ただの文字（段落）になる。
- 判定は、今と同じく**整えた生の行**で行う。文字の並びの読み方（強調・リンク・逃がし）は、今の走査（`richtext.md` の3.1節・4節）を共有する。

### 3.2 判定の順番（`richtext.md` の2節の表に足す行。レビュー用の案）

| 順 | 条件 | 種類 | 今のブロック |
|---|---|---|---|
| 5.6 | `ParseForPages` で、**本文の最初の空でない行**が `ヒーロー: ` で始まり、その後に空白以外の文字が1つ以上ある | ヒーローの導入 | 閉じる（本文の最初なので、開いたブロックは無い） |
| 5.7 | `ParseForPages` で、`ボタン: ` で始まり、その後ろを3.1節の走査で読んだ並びが、前後の空白（`unicode.IsSpace`。半角・タブ・全角）の文字を除いた後で**リンクちょうど1つ**（リンクの前後に、空白以外の文字も強調も無い） | ボタン | 直前がヒーローの導入かボタンの並びで、その並びが3つ未満なら続く。それ以外は閉じて、新しい並びを始める |
| 5.8 | `ParseForPages` で、`カード: ` で始まり、その後ろの文字の並びに**記号の `\|` がちょうど1つ**あり、その前（題名）と後（説明）がどちらも空白以外の文字を1つ以上持つ | カード | 直前がカードの並びで、その並びが12枚未満なら続く。それ以外は閉じて、新しい並びを始める |

- 最初の空でない行でない `ヒーロー: ` の行は、段落の行（順8）。ヒーローは本文に1つだけ。
- 条件に当たらない `ボタン: `・`カード: ` の行（リンクが2つ、リンクの前後に文字、`|` が0か2つ以上、題名か説明が空）は、段落の行（順8）。入力の文字は落とさない。
- 空行（順1）は、ボタンとカードの並びを閉じる。空行をはさんだボタンの行は、別の並びになる。ヒーローの導入の直後のボタンの行（空行をはさまない）は、ヒーローのボタンになる。
- 上限を超えた行は、捨てずに新しい並びを始める（4つ目のボタンは2つ目の並びの最初、13枚目のカードは2つ目の並びの最初）。
- カードの区切りの `|` は、3.1節の走査の記号の `|`。`\|` は文字。リンクのURLの中の `|` も記号として数えるので、`|` を含むURLはカードの中で使えない（URLは `\` で作った文字を許さない。`richtext.md` の5節）。
- 題名と説明の文字の並びは、見出しと同じ読み方（強調・リンク）。前後の空白を除く。
- 「空白以外の文字が1つ以上ある」は、ヒーロー・カードとも、走査して `\` を解決した**後**の文字で判定する（`ヒーロー: \` は、行末の `\` が `\` の文字になるので当たる。`カード: 　| 説明` は題名が全角空白だけなので当たらない）。
- 例（`richtext.md` の6節の「LPの部品」に書いた）: `ボタン:  [進む](/next)`（空白2つ。前置きの後ろの空白1つは前置きの一部、残りは除くのでボタン）、`ボタン: [進む](/next)　`（行末の全角空白は1節の整えで除くのでボタン）、`ボタン: x[進む](/next)`（段落）、`ボタン: \[進む](/next)`（リンクにならないので段落）、`カード: a \| b | c`（題名 `a | b`）。

### 3.4 今の本文と移行の道具への影響

- `ヒーロー: `・`ボタン: `・`カード: ` で始まる行が既にある本文は、見え方が変わり得る。

  - README の固定ページの節と、リリースの説明に、見え方が変わり得ることと、直し方（行頭を `ボタン\:` にする）を書く。

## 4. OGPの画像（段階2）

### 4.1 決まり方

| 順 | 条件 | `og:image` |
|---|---|---|
| 1 | 公開中のページで、本文の画像のうち最初の1枚が画像の機能（`features.Media`）で公開用に解決できる | その画像（`/media/…`）。幅・高さ・説明は解決した値 |
| 2 | 1でなく、自動の画像を作れる（4.3節で描く文字が全部フォントにある） | 自動の画像 `/ogp/pages/{スラッグ}-{版}.png` |
| 3 | どちらでもない | 今と同じサイト共通の画像 |

- `og:image:width`・`height`・`alt`・`twitter:card` は、選んだ画像に合わせて一式を設定する。
- Site の `layoutData` は、今は `OGImagePath`・`OGImageAlt` を毎回上書きし、大きさは1200×630に固定している。**画面が設定済みの値は上書きしない**形に直し、大きさも値として渡す（今の `Description` と同じ扱い）。
- プレビュー（管理画面）では、OGPの画像を出さない。管理者用の画像のURLを `og:image` に出さない。
- 画像の機能が無い構成、画像の解決に失敗した時は、2へ進む。画像の表（`media_items`）を固定ページから直接読まない。

### 4.2 経路

- `GET /ogp/pages/{スラッグ}-{版}.png`（`IsolatedRoutesFeature`。Cookieを発行・照合しない。HEADも同じ）。固定ページの機能が持つ。
- `{版}` は、SHA-256 の小文字16進の先頭12文字。入力は、`ogp-pages` の印、描き方の版の番号（整数の定数）、組み込んだフォントのファイルの SHA-256、題名、サイトのホスト名を、それぞれ**長さ（バイト数の10進）と `:` を前に付けて**つないだもの（区切り無しのつなぎで `ab`+`c` と `a`+`bc` が同じにならないように）。題名やホスト名を変えると版が変わり、古いURLは404になる。
- 描き方の版の番号: 描く結果のPNGが変わる変更（色・配置・禁則・折り返し・`x/image` の更新で描画が変わる時）では、番号を1つ上げる。決まった入力（題名3つ）のPNGの SHA-256 を試験に固定し、番号と一緒に持つ。描画が変わったのに番号が同じなら、試験が落ちる。フォントを替えた時は、フォントのハッシュで版が自動で変わる。
- 返すのは、**今公開中**のページで、版が今の題名と一致する時だけ。公開中かの判定は、公開の表示と同じ `Store.Published`（予約の時刻を含む）を使う。それ以外（下書き、予約の前、非公開、無いページ、版の違い、4.3節の文字が足りない、ファイル名が `{スラッグ}-{12桁の16進}.png` の形でない）は、Siteの404。DBの障害は500（公開の表示と同じく、404にしない）。
- 成功の応答だけ `Content-Type: image/png`、`Cache-Control: public, max-age=31536000, immutable`（版がURLに入るので変わらない）。404・500・503は `no-store`。HEADは本文を返さない。受け取ったCookieは読まず、セッションを作らず・延ばさない。非公開に戻した後も、Cloudflare 等に残った画像は期限まで配られ得る（守らない範囲。今の `/media/` と同じ扱い）。
- 同時に作る数は2つまで（超えたら待たずに503）。作り終えたら、失敗でも枠を返す。作るのは1枚10〜20ms（試作）。保存はしない。
- 経路は `GET /ogp/pages/{name}` だけを登録する。`/ogp`・`/ogp/` そのものは登録しないので、スラッグ `ogp` の固定ページと共存する。

### 4.3 描き方

- 1200×630。背景、上端の帯、題名（最大3行）、下にサイトのホスト名（`SITE_URL` のホスト。Site のレイアウトはサイト名をテンプレートに直接書いていて、共通の値が無いため。ASCIIなので欠字にならない。国際化ドメイン名は Punycode のまま）。色はキットの既定の色で固定する（テーマ `theme.css` の色は使わない。9節の5）。
- フォント: Noto Sans CJK JP Bold を、JIS X 0208 の文字（第1・第2水準・記号・かな）と ASCII に絞ったもの（約1.5MB、OFL 1.1）。`internal/web/ogimage/` に置く。
  - 記録すること（同じ場所の `FONT.md`）: 元のファイルの取得元（上流 `notofonts/noto-cjk` のリリースの版）、元のファイルの SHA-256、著作権表示、予約フォント名の有無、絞った文字の一覧の作り方と fontTools の版・引数。2026-11-06 の試作は Debian の `fonts-noto-cjk 1:20240730` の `NotoSansCJK-Bold.ttc`（SHA-256 `faa5f365…`）の0番目から作った。実装では上流のリリースから取り直す。

- 描く文字（題名、`…`、ホスト名）に**フォントに無い文字が1つでもあれば、自動の画像は作らない**（4.1節の3へ）。豆腐（□）を出さない。題名の中のタブ・改行は保存の検査で入らない。結合文字（濁点の結合、異体字セレクタ等）と、幅が0の書式文字（`unicode.Cf`）も「フォントに無い文字」として扱う。

- 部品は Core（`internal/web/ogimage`）に置き、お知らせ・カタログに広げる時にも使えるようにする（この計画では固定ページだけ）。

### 4.4 試験

- 決まり方: 画像あり（公開中の記事で共有・非公開・解決失敗）、画像の機能が無い構成、フォントに無い文字、Siteが無い構成。
- 経路: 公開中・下書き・予約の前と後・非公開に戻した後・無いページ・版の違い・ファイル名の形の違い・ハイフンを含むスラッグ・HEAD（本文なし）・DBの障害（500、`no-store`）・Siteが無い構成。Cookie: 既存・不正のCookieを付けても、`Set-Cookie` が無く、セッションの表が変わらない。`Cache-Control`（成功だけ immutable）。同時の上限の503と、失敗の後も枠が戻ること。`/ogp` という固定ページが公開できること（経路が取られない）。
- 描画: 同じ入力で同じバイト列になること。決まった入力のPNGのハッシュと描き方の版の番号の組（4.2節）。版の入力の区切り（`ab`+`c` と `a`+`bc` で版が違う）。4.3節の折り返しの例。
- 依存: `test/architecture_test.go` の直接依存の許可の一覧に `golang.org/x/image` を足す。組み込まれる部品の一覧の検査は、**サーバーと移行の道具（`cmd/wpimport`）で別々の期待値**を持つ形に直す（今は移行の道具の期待値を「サーバーの一覧＋`x/net`」で作っているので、サーバーだけが使う `x/image` を足すと移行の道具にも要求してしまう）。`x/text` は「`go.mod` にある」ことと「サーバーに組み込まれる」ことを分けて確かめる。
- ライセンス: LICENSE と FONT.md があること、`licenses` のコマンドが著作権表示とライセンスの全文を出すこと。

## 5. LPとSEOのスキル（段階3）

`skills/minimal-web-kit-lp/SKILL.md`（150行以内）を足す。規約は `minimal-web-kit-design` 等を参照し、写さない。

1. 切り口を1ページに1つに絞る（相手、困りごと、言葉）。営業資料や社内の文書から起こす時は、資料に無い主張を足さない。

4. サイトの中からのリンク: 新しいLPは、ナビに出すページかトップから必ずリンクする。公開中の固定ページは、ナビに出さなくても `sitemap.xml` に載る（検索に載せない方法はキットに無い）。

6. OGPの画像: 何もしなければ題名から作られる。写真を使うなら、横長の画像を本文の最初の画像にする（ヒーローの後でよい）。

8. 約束しないこと: 順位、問い合わせの増加、未検証の数字（`minimal-web-kit-design` の5節）。
9. MCPで下書きを作り、人が確かめて公開する（AIが無断で公開しない）。
