# 切り口ごとのLP 実装計画

状態: 計画のレビュー待ち（2026-11-06）。対象の時点は `615e4b2`。

## 1. 目的と範囲

1つの製品を、相手と切り口ごとに別のページ（LP）で説明し、資料・SNS・検索から直接その入口へ送れるようにする。新しい機能は作らず、固定ページ（`features/pages`）と本文の記法（`internal/web/richtext`）を広げる。

2026-11-06 に紹介サイトで、今の固定ページだけでLPを2つ作って公開した（`/lp-wordpress`・`/lp-content-flow`）。URL、見出し、箇条書き、番号つきの手順、表、リンク、狭い画面、Cookie無し、`title`・`description`・`canonical`・OGP・`sitemap.xml` は今のままで足りた。足りなかったのは次のとおり。

| # | 足りない物 | この計画での扱い |
|---|---|---|
| 1 | 行動を促すボタン（今は文字のリンクだけ） | 段階1。本文の記法に「ボタンの行」を足す |
| 2 | 最初の画面の力（題名が普通の見出し、導入が普通の段落） | 段階1。本文の先頭の決まった形をヒーローとして描く |
| 3 | 利点を横に並べるカード（今は小見出しと段落の縦の並び） | 段階1。本文の記法に「カードの行」を足す |
| 4 | ページごとのOGPの画像（今はサイト共通の1枚） | 段階2。本文の最初の画像をOGPの画像にする（保存の項目は増やさない） |
| 5 | LPを書く人・AIがSEOと切り口を意識する手引き | 段階3。スキルを足す |
| 6 | どのLPから問い合わせが来たか | この計画の範囲外。承認境界2に当たるので、段階1〜3を使ってから別に決める（10節） |
| 7 | よくある質問などの構造化データ（JSON-LD） | 範囲外。`<script>` の要素をテンプレートに書かない決まりと、CSPとの関係を別に調べる |

作らない物: 自由なHTML・CSSの欄、ページごとのレイアウトの選択、A/Bテスト、フォームの項目の自由な作成、LP専用の機能・表・管理画面。

| 3. 外部通信 | 当たらない | |

## 3. 本文の記法に足す行（段階1）

固定ページの本文だけで読む。社内文書（`richtext.Parse`）は今のまま読み、同じ行は段落の行になる。今の `ParseWithImages` と同じ分け方で、`ParseForPages`（仮）を足すか、`ParseWithImages` を広げる（実装の時に決める。社内文書の読み方は変えない）。

前置きの形は、今の `表: ` に揃えて、日本語の名前と半角のコロンと半角スペース1つにする。

### 3.1 ボタンの行

```text
ボタン: [ご相談・お問い合わせ](/contact)
ボタン: [機能の一覧を見る](/bundled-features)
```

- 行全体が `ボタン: ` と、リンク1つ（`[文字](URL)`、URLの許可は今のリンクと同じ `richtext.md` の5節）だけのとき、ボタンになる。リンクの前後に文字があれば、段落の行（今と同じ読み方）。
- 続くボタンの行は1つの並び（`div`）にまとめる。並びの最初は `btn btn-primary`、2つ目からは `btn btn-secondary`。
- 外のURL（`https://`）は、今のリンクと同じく新しいタブで開く表示と `rel` を付ける。
- 1つの並びは3つまで。超えた分は段落の行として読む（上限は黙って捨てない形にする）。

### 3.2 カードの行

```text
カード: 預かる情報が少ない | 氏名や連絡先を初期設定では集めません。
カード: 更新する部品が少ない | アプリの更新は、実行ファイル1つを置き換えるだけです。
カード: 足しても崩れにくい | 公開前の自動の検査で止まります。
```

- 行が `カード: ` で始まり、その後に、逃がしていない `|` が1つだけある時、カードになる。`|` の前が題名（`h3`）、後が説明（段落。強調とリンクを使える）。題名と説明は空にできない。
- 続くカードの行を1つの並びにまとめ、数が3か6なら `grid-3`、それ以外（2・4・5…）は `grid-2` にする。1つの並びは12枚まで。
- `|` が無い・2つ以上、題名か説明が空の行は、段落の行（今と同じ）。
- カードの題名は `h3` なので、見出しの階層は「直前の `## ` の下」になる。直前に `## ` が無いカードの並びは、見出しの順が飛ぶ（`h1` の次が `h3`）。保存の時に、管理画面で警告だけを出す（拒否しない）。

### 3.3 ヒーロー

新しい行の種類は足さない。本文が**段落1つ＋ボタンの並び1つ**で始まるとき、ページの題名・その段落・そのボタンの並びを、トップと同じヒーロー（`section.hero`）として描く。

- それ以外の始まり方なら、今と同じ見え方（題名の `h1` と本文）。
- ヒーローの段落は、今と同じく `description` の元になる（`features/pages` の `description`）。

### 3.4 今のページへの影響

- `ボタン: `・`カード: ` で始まる行が既にある本文は、見え方が変わる。実装の前に、移行の道具（`cmd/wpimport`）が作る本文と、キットの見本・試験のデータに、この形の行が無いことを確かめる。アプリの運営者には、リリースの記録（README の変更の節）で知らせる。
- 本文が段落とボタンで始まるページは、今は存在しない（ボタンの行が無い）ので、ヒーローに変わるページは無い。

### 3.5 読み方の規則と試験

- `docs/richtext.md` の「行の種類を決める順番」の表に、ボタンの行とカードの行を足す。順番の位置（表の説明・画像の行との前後）と、`\|`・`\[` 等の逃がし方を、例と一緒に表で固定する。実装の前に、この表だけを短くレビューに出す（`minimal-web-kit-design` の3節の6）。
- 表の例を全部、単体の試験にする。意地悪な入力（`ボタン: [[[`、`カード: ||||…`、長い行）で、読む時間が入力の長さに比例することを測る。
- ファズで、HTMLが崩れないこと、許可したURLだけ、入力の文字を落とさないこと（ボタンとカードの文字も含む）を確かめる。
- 管理画面のプレビュー・公開の表示・MCPの `pages_create`・`pages_update` の説明（使える書き方）を揃える。

## 4. ページごとのOGPの画像（段階2）

- 本文に画像の行があれば、最初の画像を `og:image` にする。幅と高さは画像の表（`media_items`）の値を使い、`og:image:alt` は画像の行の説明文。
- 画像が無ければ、今と同じサイト共通の画像。
- 画像は公開中の記事から使われている間だけ `/media/` で配信されるので、公開中のページの画像は配信される。下書きのプレビューでは出さない。
- 画像は長辺1,600pxに縮めて保存するため、縦横比はOGPの推奨（1.91:1）と違うことがある。SNSでの切り抜かれ方は守らない範囲にし、段階3のスキルで「横長の画像を最初に置く」と案内する。
- Site の `layout` が持つ `OGImagePath`・`OGImageAlt` を、固定ページの公開の表示で上書きする形にする。ほかの機能（お知らせ・カタログの代表画像）は、この計画では変えない。

## 5. LPとSEOのスキル（段階3）

キットのスキルには、LPを書く時に切り口や検索を意識させるものが無い。`skills/minimal-web-kit-lp/SKILL.md`（仮、150行以内）を足し、次を扱う。

1. 切り口を1ページに1つに絞る（相手、困りごと、言葉）。営業資料や社内の文書から起こす時は、資料に無い主張を足さない。
2. 検索する人の言葉で、`##` の見出しと最初の段落を書く。題名は `title` に、最初の段落は `description`（120文字まで）になる。
3. 最初の画面: 段落1つ＋ボタンでヒーローになる。ボタンは1〜2個。
4. サイトの中からのリンク: 新しいLPは、ナビに出すページ（例: 同梱機能）かトップから必ずリンクする。公開中の固定ページは `sitemap.xml` に載る。
5. 同じ製品のLP同士で、文が重なりすぎないようにする（`canonical` は各ページ自身を指す）。
6. OGPの画像: 横長の画像を本文の最初に置く。
7. 公開の後: Search Console へのサイトマップの送信、検索の結果の確かめ方。アクセス解析を使う時は、同意した人の分だけ数えることを前提にする。
8. 約束しないこと: 順位、問い合わせの増加、未検証の数字。`minimal-web-kit-design` の5節の表現の決まりに従う。
9. MCPで下書きを作り、人が確かめて公開する流れ（AIが無断で公開しない）。

README の「AI開発スキル」の数と一覧、`test/readme_test.go` が見る箇所も直す。スキルを増やさず `minimal-web-kit-design` の節にする案もある（10節）。

## 9. 守らない範囲・残るリスク

- 検索の順位と、問い合わせの増加。
- SNSがOGPの画像をどう切り抜くか。
- 本文の記法の行の形を後から変えること（変えると、書いた本文の見え方が変わる）。
- 自由なレイアウト。並びの形はボタン・カード・ヒーローの3つに限る。
