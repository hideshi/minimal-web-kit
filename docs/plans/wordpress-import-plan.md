# WordPressからの移行 実装計画

状態: 案（2026-11-03）。利用者が2節の決定と、承認境界1・2を承認した。未実装。計画のレビューの前。対象の時点は `main` の `ba32510`。関連する正本: [お知らせ](../domain/news.md)、[固定ページ](../domain/pages.md)、[画像](../domain/media.md)、[本文の書き方](../richtext.md)。

## 1. 目的と範囲

宣伝サイトの営業資料は「WordPressから自動で移す道具はありません」と書いていて、乗り換えの提案で引っかかりやすい。WordPressの書き出し（WXR）と画像のフォルダから、キットへ内容を移す道具を作る。

この計画は3つの変更を含む。

1. お知らせの本文で、リンクの記法 `[文字](URL)` を読む。
2. お知らせに専用のカテゴリを足す（1記事に1つ）。
3. 移行の道具（別の実行ファイル `cmd/wpimport`）。

作らないもの: テーマ・見た目・ページビルダーのレイアウトの再現、プラグインの機能、コメント・ユーザー・お問い合わせのプラグインの受信データの移行（個人情報のため、あえて移さない）、元のサイトからの画像のダウンロード（外部通信になる）、キットの中の転送の機能、WordPressの他の書き出しの形式（データベースの直接の読み取り等）。

## 2. 決まったこと（2026-11-03）

| 事項 | 決定 |
|---|---|
| お知らせのリンク | 本文で `[文字](URL)` の記法だけを読む（案B）。見出し・リスト・表は読まない |
| お知らせの分類 | お知らせ専用のカテゴリ。カタログとはデータを共有しない。1記事に1つ。管理画面と絞り込みの部品は共通にしてよい |
| 移行の道具 | 別の実行ファイルにし、その実行ファイルだけ `golang.org/x/net/html` を使う。本番のサーバーの依存は増やさない |
| 古いURL | 対応表をCloudflareの一括転送（Bulk Redirects）のCSVで書き出す。キットに転送の機能は足さない |
| 画像 | 全部移す。手元に取ってきたアップロードのフォルダを読み、通信はしない |
| 移した記事 | 全部下書きにする。人が確かめてから公開する |

## 3. お知らせのリンク

- 本文を段落と行に分ける今の読み方（`form.Paragraphs`）は変えず、各行の中だけを `richtext` の文字の並びの規則で読む。読むのはリンクだけで、強調（`**`）は文字のまま。`docs/richtext.md` の4節・5節の規則（`https://` とサイト内のパスだけ、`\` で逃がせる）をそのまま使う。
- `richtext` に、行の中のリンクだけを読む入口を足す（例: `richtext.LinksOnly(line)`）。読む時間は行の長さに比例すること、許可しないURLは文字のまま出すことを、今の規則のテストと同じ形で確かめる。
- 既存の記事: 本文に `[文字](URL)` の形がある記事は、配備の直後からリンクとして表示される。移行の前に、既存の記事にこの形があるかを数えるコマンドの出力か、テストの手順で確かめる。`\[` で文字として書ける。
- 本文の `\` の扱い: リンクの記法の外の `\` は今までどおり文字として出すか、記法と同じく逃がしとして読むかを、記法の規則のレビューで決める（9節）。既存の記事の見え方が変わらない方を優先する。
- APIの `/api/news` の本文は、記法の文字のまま返す（NEWS-INV-7 の項目は変えない）。README とAPIの説明に、記法を書く。
- 管理画面の本文の説明に、リンクの書き方を足す。

## 4. お知らせのカテゴリ

| 表・列 | 内容 |
|---|---|
| `news_categories` | id、名前（1〜50字、正規化して重複させない）、作成日時 |
| `news_posts.category_id` | NULLを許す。`news_categories(id)` への外部キー、`ON DELETE SET NULL` |

- 列の追加は `pragma_table_info` で有無を見て `ALTER TABLE ... ADD COLUMN` で行う（画像の代表画像の列と同じ形）。表は作り直さない。
- 管理画面: カテゴリの一覧＋追加、編集、削除の確認（カタログの分類の画面の型と同じ）。記事の作成・編集で選ぶ（`field` の選択）。カテゴリを消しても記事は消えない。
- 公開: `/news?category=ID` で絞り込む。公開中の記事を持つカテゴリだけを候補に出す。ページ送りは条件を残す。公開キャッシュの扱いは今の `/news` と同じ。
- API: `/api/news` の項目にカテゴリを足すかは、NEWS-INV-7 を変えるため、今回は足さない。
- MCP: お知らせのツールはカテゴリを変えない。対象の状態のハッシュと、`*IfUnchanged` の条件にカテゴリを含める（画像の代表画像と同じ扱い）。
- 共通にする部品: 分類の名前の検査と、管理画面の分類のテンプレートは、カタログと共通にできるかを実装のときに確かめる。データは共有しない。

## 5. 移行の道具（`cmd/wpimport`）

### 5.1 使い方

```sh
# 試しに読むだけ（DBを変えない）
wpimport -wxr export.xml -uploads ./wp-content/uploads -old-origin https://old.example.com -new-origin https://example.com -report report.md -dry-run
# 取り込む（サーバーを止めて、DBの複製に対して実行する）
wpimport -wxr export.xml -uploads ./wp-content/uploads -old-origin https://old.example.com -new-origin https://example.com -db app.db -report report.md -redirects redirects.csv
```

- サーバーを止めて実行する（同じDBへの同時の書き込みを避ける）。取り込みの前に `store.Backup` で複製を作る。
- 取り込みは、記事ごとに保存の検査（各機能の保存の関数）を通す。DBへ直接書かない。画像は画像機能の加工（縮小・再エンコード・EXIFを落とす）を通す。
- 同じ入力で2回実行しても、二重に取り込まない（WordPressの記事のIDと画像のファイルを記録して飛ばす。記録の置き場所は13節で決める）。
- 外部へ通信しない。

### 5.2 対応

| WordPress | キット | 扱い |
|---|---|---|
| 固定ページ（`page`、公開・下書き） | 固定ページの下書き | 本文を `docs/richtext.md` の記法に変換する。スラッグは `post_name` を使い、キットの形と予約語に合わなければ作り直して報告する。親子のページは1階層にして報告する |
| 投稿（`post`） | お知らせの下書き | 本文を段落とリンクの記法に変換する。公開日時は `post_date_gmt` を使う。最初のカテゴリをお知らせのカテゴリにし、残りとタグは報告する |
| 添付（`attachment`）とアップロードのフォルダ | 画像 | 元の画像だけを取り込む（WordPressが作る `-300x200` 等の版は飛ばす）。説明は代替テキスト（`_wp_attachment_image_alt`）、無ければ題名。どちらも無ければ報告する |
| アイキャッチ（`_thumbnail_id`） | お知らせの代表画像 | |
| 固定ページの本文の画像 | 画像の行 | 本文の中の `<img>` を、取り込んだ画像の行にする。見つからなければ説明の文字にして報告する |
| お知らせの本文の画像 | 報告 | 記法が無いため。アイキャッチが無ければ、最初の画像を代表画像にする |
| 予約投稿（`future`） | 下書き＋公開日時 | 公開は人が行う |
| 非公開・ゴミ箱・リビジョン・自動保存 | 取り込まない | 報告に件数だけを出す |
| コメント、ユーザー、作者の名前とメールアドレス | 取り込まない | 報告にも個人情報を書かない |
| カスタム投稿タイプ、独自フィールド、メニュー、ウィジェット | 取り込まない | 報告に種類と件数を出す |

### 5.3 本文の変換

`golang.org/x/net/html` で読み、決めた要素だけを記法に変える。それ以外は中の文字だけを残す。

| HTML | 固定ページ | お知らせ |
|---|---|---|
| `h1`・`h2` | `## ` | 段落 |
| `h3`〜`h6` | `### ` | 段落 |
| `p`、`br` | 段落、行 | 段落、行 |
| `ul`・`ol`（入れ子は1段にする） | `- `・`1. ` | 行頭の `・` |
| `table`（結合のある表は報告） | 表 | 文字 |
| `a`（`https://`・サイト内） | `[文字](URL)` | `[文字](URL)` |
| `a`（`http://`・`mailto:` 等） | 「文字（URL）」 | 「文字（URL）」 |
| `strong`・`b` | `**文字**` | 文字 |
| `img` | 画像の行 | 報告 |
| `script`・`style`・`iframe`・`form`・`embed` | 捨てて報告 | 同じ |
| ショートコード（`[gallery]` 等）、ブロックのコメント | 捨てて報告 | 同じ |

- 本文の文字の中の記法の記号（`*`・`[`・`]`・`|`・行頭の `#`・`-`・数字と `.` 等）は `\` で逃がし、意図しない記法にしない。変換した本文を `richtext.ParseWithImages` で読み、文字が落ちていないことを確かめる（ファズ）。
- 古いサイトの中へのリンク（`-old-origin` の下）は、対応表で新しいURLへ書き換える。見つからないものは古いURLのまま残して報告する。
- 本文の長さ・表の上限を超えるものは、取り込まずに報告する。

### 5.4 転送のCSV

- 1行に `古いURL,新しいURL,301`。見出しの行は入れない（Cloudflareの形式）。
- 古いURLは、パーマリンク（`link`）と `?p=ID` の形の両方を出す。クエリは一括転送のソースに書けないため、`?p=` の形は報告に回す。末尾の `/` の有り無しは両方の行を出す。
- 無料プランの上限は合計10,000件。超えるときは報告で知らせる。
- 2026-11-03 に Cloudflare の公式の資料で形式と上限を確かめた。資料の間で `preserve_path_suffix` の既定値の書き方が食い違っているため、列は省かずに書く。

### 5.5 報告

Markdown で、取り込んだ件数、飛ばした物と理由、変換で落ちた要素、画像の合計の容量と上限、説明の無い画像、転送の件数を書く。記事の本文、作者、メールアドレスは書かない（題名とIDまで）。

## 6. 文書とテスト

文書:

- `docs/domain/news.md`: リンクの記法、カテゴリの用語・不変条件・権限。
- `docs/richtext.md`: お知らせの行の中で読むリンクの規則。
- `docs/data-inventory.md`: `news_categories` と `news_posts.category_id`。
- `docs/ui/use-cases.md`: カテゴリで絞り込む、移行する。
- `README.md`、`docs/deploy.md`（移行の手順）、`docs/components.md`。
- 移行の道具の使い方と、移らない物の一覧（営業資料の説明に使う）。

テスト:

- リンク: 規則の表の例、許可しないURL、既存の本文の見え方、APIの本文、読む時間。
- カテゴリ: 保存・削除・絞り込み・下書きのカテゴリを公開の候補に出さない、MCPの競合。
- 変換: 要素ごとの表、記号の逃がし、ショートコード、壊れたHTML、変換の結果を読んで文字が落ちないこと（ファズ）。
- 取り込み: 小さな見本のWXRと画像のフォルダで、件数・下書き・画像・代表画像・内部リンクの書き換え・2回目の実行・試しの実行でDBを変えないこと。個人情報が報告とDBに残らないこと（目印の値）。
- 依存: `test/architecture_test.go` の許可リストに `golang.org/x/net` を足し、`./cmd/server` の実行ファイルには入らないことを確かめる。
