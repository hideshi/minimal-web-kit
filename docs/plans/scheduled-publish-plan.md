# カタログと固定ページの予約公開の計画

状態: 実装済み（2026-11-02）。列の追加と入力欄は利用者が承認。計画のレビューはSol、完成のレビューはFable。対象の時点は `7b14912`。実装の後、今の仕様は `docs/domain/catalog.md`・`pages.md` に移す。

## 目的

新商品の発表、採用ページの募集開始、キャンペーンのように、決まった時刻に項目やページを出したい。今は、その時刻に誰かが管理画面で「公開する」を押す必要がある。お知らせと同じ操作で、公開の開始日時を予約できるようにする。

## 承認が要る事項

- **保存データの追加（境界2）**: `catalog_items` と `pages` に列 `publish_at`（INTEGER、NULL可）を足す。編集画面に入力欄「公開日時（任意）」を足す。個人情報は入らない。保持は行と同じで、行の削除で消える。
- 依存、外部通信、CSS・JS、公開範囲は変えない。

## 決めること（案）

| 事項 | 案 | 理由 |
|---|---|---|
| 列の意味 | `publish_at` は「公開を始める日時」。公開ページに日付としては出さない | お知らせの `published_at` は記事の日付として表示する別の意味なので、名前を分ける |
| 公開の判定 | `status = 'published' AND (publish_at IS NULL OR publish_at <= 今)` | 既存の公開中の行は `NULL` のままで公開を続ける。移行で値を埋めない |
| 公開の操作 | 公開日時が未来なら、「公開する」は「公開を予約する」になり、時刻まで出ない。過去か空なら今すぐ公開 | お知らせと同じ |
| 非公開の操作 | 「非公開（下書き）に戻す」で `publish_at` を `NULL` に戻す。予約中は「予約を取り消す（下書きに戻す）」 | 次に公開するときに古い予約が残らない |
| 空欄での保存 | 今の公開日時を変えない。予約をやめるのは「予約を取り消す」で行う | お知らせと同じ。空欄の保存で予約中の項目が即時に公開される事故を防ぐ |
| 公開中のものを未来の日時に | 拒否し、先に非公開に戻すよう案内する | 編集の保存で、公開中のページが黙って消えるのを防ぐ（お知らせのMCPは確認の文で警告している。画面とMCPで同じ扱いにする） |
| 時刻の単位とタイムゾーン | 分。サーバーのタイムゾーン（`TZ`）で読む | お知らせと同じ |

## 設計

### 時刻の読み取りの共通化

お知らせの `parsePublishedAt` を `internal/web/form` の `ParseLocalDateTime` に移し、3つの機能で使う。秒付きの値も受け付け、1970年より前は拒否する。表示は既存の部品 `datetime`。

### カタログ

公開の判定を1つの式（`publicCondition(now)`）にまとめ、次の全部で使う。

- `Store.Get`・`Store.List`（通常と断片）、`Store.Classifications`（分類の候補）、`SitemapEntries`、`publishedCover`（画像の公開の判定）

公開一覧はキャッシュしないので、時刻を過ぎた次の要求から見える。

### 固定ページ

- `Store.Published`（公開ページ）、`publishedUses`（画像）、`SitemapEntries` は、要求のたびに今の時刻で判定する。
- **ナビ**: 今は公開の操作のたびに作り直すため、時刻が来ても変わらない。作り直す材料に `publish_at` を含め、`DynamicNavLinks` が呼ばれるたびに今の時刻で絞る。タイマーは使わない。トップ等の公開キャッシュ（60秒）の分だけ遅れて見える。
- 予約中のページは、下書きと同じ404にする（PAGES-INV-1）。プレビューは今どおり管理者だけ。

### 画面

- 編集画面に `publish_at` の入力欄（`field` の部品、`datetime-local`）を足す。説明は「未来の日時を指定して『公開を予約する』を押すと、その日時から公開されます。時刻はサーバーのタイムゾーンです」。
- 「公開と削除」の節（`publish-actions`）のボタンの文言を、状態で4通りにする（公開する、公開を予約する、非公開（下書き）に戻す、予約を取り消す（下書きに戻す））。
- 一覧の状態の列は、予約中を「公開予約（日時）」と出す。お知らせの一覧と同じ書き方。
- 新しい画面は作らない。

### MCP

- 作成・編集の引数に `publish_at` を足す。確認の文に、予約公開になる旨と日時を出す。
- 確認の対象の状態（`mcpState`）に `publish_at` を含める（MCP-INV-4）。
- 公開のツールは、保存済みの日時に従う。日時が未来なら「予約公開します。公開日時: …」と確認に出す。

### 移行

`ALTER TABLE ... ADD COLUMN publish_at INTEGER`（NULL可）。表の作り直しは要らない。列が無いときだけ足す（`pragma_table_info` で確かめる）。CHECKは付けない。既存の行は `NULL` のままで、今の公開の状態を変えない。前の版の実行ファイルは足した列を無視して読み書きできるので、戻すときは実行ファイルだけでよい。ただし、戻している間は予約中の項目がすぐ公開に見える。これは戻し方の注意として配備の記録に書く。

## 不変条件（docs/domain の更新案）

- CATALOG-INV-1・PAGES-INV-1: 「公開中」を「公開の状態で、公開日時を過ぎたもの」に読み替える。予約中は下書きと同じ扱い（一覧、詳細、分類の候補、sitemap、画像、ナビ）。
- 新 CATALOG-INV-13・PAGES-INV-11: 空欄の保存は公開日時を変えない。公開中のものを未来の日時にする保存は拒否する。非公開に戻すと公開日時を消す。
- PAGES-INV-6: ナビは公開日時を過ぎたものだけで、時刻を過ぎた後の最初の描画から載る。
- MEDIA-INV-1 は「予約公開の日時を含む」と既に書いてあり、カタログと固定ページにも当てはまる。

## テスト

- 境界の時刻: 公開日時の1秒前と同時刻で、公開ページ、一覧、分類の候補、sitemap、ナビ、画像の各経路が404・非表示から表示に変わる。時計は差し替えられる `now` で動かす。
- 移行: 列の無い表から起動して列が足され、既存の公開中の行が公開のままであること。2回起動しても変わらないこと。
- 操作: 4通りのボタン、空欄の保存、公開中を未来にする拒否、非公開での `NULL` 化。
- MCP: 確認の文、状態のハッシュの変化で保存しないこと。
- `adminSamples` に予約中の項目とページを足す。`docs/data-inventory.md` の6節と8節に列を足す（台帳のテストが照合する）。
- ユースケース: UC-CATALOG-4・UC-PAGES-4 の目的に「決めた時刻に」を足す。

## 守らない範囲

- 公開の終了日時（期間限定の掲載）。必要なら別の計画にする。
- 時刻ちょうどの反映の保証。判定は要求の時刻で、トップ等の公開キャッシュの間（最大60秒）は前のナビが見えることがある。
- 予約の通知、予約の一覧画面。

## 採らなかった案

- **お知らせと同じ `published_at` の名前と意味（記事の日付）**: カタログと固定ページは日付を表示しないので、意味が合わない。
- **タイマーで公開の状態を書き換える**: 起動していない間や時刻のずれで取りこぼす。要求のたびに判定するほうが単純で、状態の書き込みも要らない。
- **移行で既存の公開中の行に今の時刻を入れる**: 値が要らず、移行を失敗しうる処理を増やすだけになる。

## 計画のレビュー（Sol）で直したこと

| 重大度 | 指摘 | 直したこと |
|---|---|---|
| 高 | ナビの作り直しが逆の順で終わると、古い予約日時・公開状態が戻る | 作り直しを `rebuildMu` で直列にし、失敗したときにナビを空にする処理も同じ範囲に入れた。読み取りの直後で止めて再現するテストを置いた（ロックを外すと落ちることを確認） |
| 高 | 固定ページのMCPの照合に公開日時が無い | `SaveIfUnchanged`・`SetPublishedIfUnchanged` の照合に `publish_at IS ?` を足した |
| 高 | 公開中を未来にする拒否は、保存の時点のDBで不可分に判定する必要がある | 保存のトランザクションの中で今の行と時刻を読む `checkPublishAt` にした。「公開中」は公開日時を過ぎたものと定義した |
| 中 | 入力しただけでは公開の要求に日時が送られない | 説明を「日時を入れて保存してから『公開を予約する』を押す」にした。編集画面の状態も予約中を出す |
| 中 | MCPの読み取りと確認の文が予約を区別できない | 読み取りに `publish_at` を返し、対象の行と確認の文に予約中・予約公開を出す。作成は「公開の操作をすると、この日時から公開される」と書く |
| 中 | 前の版へ戻したときの説明 | 下の「戻すとき」に分けて書いた |

## 戻すとき

列を足すだけなので、前の版の実行ファイルはそのまま動く。ただし前の版は公開日時を見ないため、戻している間は予約中の項目とページが、本文・一覧・分類の候補・ナビ・`sitemap.xml`・画像のどれにもすぐ出る。また前の版で非公開にすると日時が残り、今の版へ戻した後に「非公開で日時を消す」の決まりを満たさない行ができる（次に公開すると古い日時で予約になる）。新しい版で日時を保存した下書きを前の版で公開すると、前の版ではすぐ出て、今の版に戻した後に公開日時を過ぎていればそのまま公開を続ける。予約を秘匿したまま戻すには、先に今の版で予約中のものを下書きに戻してから、前の版へ戻す。

静的書き出しは、カタログと固定ページを有効にすると今までどおり使えない。

## 完成のレビュー（Fable）で直したこと

| 重大度 | 指摘 | 直したこと |
|---|---|---|
| 中 | 予約中に過去の日時を保存すると、公開の操作なしで公開されるのに、伝えていない | 拒否はしない（すぐ出したい場合の操作が増えるため）。管理画面は完了の案内を「公開日時を過ぎているため、公開ページに出ています」にし、MCPは確認の文に警告を出す。状態遷移図と不変条件に足した |
| 中 | 固定ページの `mcpState` から公開日時を外してもテストが落ちない | MCPのツールの Prepare と Apply を通して、確認の後に日時だけが変わったら止まるテストを足した |
| 低 | 管理画面のテストの「公開を予約する」が欄の説明に当たっていた | ボタンの形で照合し、固定ページにも同じテストを足した |
| 低 | 下書きの日時を消す手段の説明が無い | 欄の説明と状態の節に書いた |
| 低 | 前の版で公開した場合の注意 | 「戻すとき」に足した |
