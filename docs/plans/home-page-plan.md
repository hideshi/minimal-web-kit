# トップページを固定ページで書く 実装計画

状態: 計画（2026-11-26）。実装の前に、外部のモデルのレビューを受ける（本文の記法を足し、`/` の応答を変えるため。`minimal-web-kit-design` の3節の5・6）。

## 1. 目的と範囲

トップページ（`GET /`）を、コードを書き換えずに、管理画面とMCPから直せるようにする。新しい編集の仕組みは作らず、固定ページ（`features/pages`）の1件をトップに使う。今の固定ページの記法では、紹介サイトのトップ（`features/site/views/index.html`）にある部品の多くを書けないので、よく使う部品を本文の記法に足す。

部品は、主なCMS（WordPress・Squarespace・STUDIO・Shopify）が標準で持つ部品を公式の資料で調べ（2026-11-26。Shopifyの既定のテーマ・Wix・Jimdo の一覧は読めなかった）、JSも外への通信も要らないものから選んだ。

| # | 部品 | 出どころ | 扱い |
|---|---|---|---|
| 1 | よくある質問（開閉） | 2サービス・紹介サイトのトップ | 足す（3.2節） |
| 2 | 最新のお知らせ（カテゴリで絞って新着N件） | 2サービス（最新の投稿の一覧） | 足す（3.3節・4節） |
| 3 | お問い合わせのボタン | 3サービス（フォーム）・紹介サイトのトップ | 足す（3.4節・4節） |
| 4 | 引用・お客様の声 | 2サービス | 足す（3.5節） |
| 5 | 締めの帯（CTA） | 紹介サイトのトップ | 足す（3.6節） |
| 6 | 手順の並び | 紹介サイトのトップ | 足す（3.7節） |
| 7 | 見出しの飛び先と目次 | 1サービス・紹介サイトのトップ | 足す（3.8節） |

作らない物:
- 動画・埋め込み（地図・SNS）・カルーセル・予約: 外への通信かJSが要る（承認境界3・4・5）。リンクで代える。
- 小さな札（バッジ）・2段のボタン・文中のコード・区切り線: 見た目の飾りで、無くても伝わる。
- 自由なHTML・CSSの欄、ページごとのレイアウトの選択、部品の並べ替えの画面。
- 紹介サイトのトップの書き換え（キットの `features/site` は今のコードのまま。運用のサイトが選んで移る）。

## 2. 承認境界

| 境界 | 判定 | 内容 |
|---|---|---|
| 1. `go.mod` | 当たらない | 標準の `html/template` と今の部品で作る |
| 2. 保存データ | 当たらない | 表・列・フォームの項目を足さない。トップに使うページは環境変数で指定する（5節） |
| 3. 外部通信 | 当たらない | お知らせはサイトの中のDBから読む |
| 4. CSS・JS | 当たらない | 紹介サイトのトップが使う `style.css` のクラス（`faq-item`・`step-list`・`cta-banner` 等）を使う。引用の規則は `style.css` の中に足す。JSは使わない |
| 5. 公開範囲 | 当たらない（確認したい） | 新しい公開の経路は足さない。指定したとき、`/` の中身が固定ページに替わり、`/{スラッグ}` は `/` へ転送する（5節）。公開済みの内容が別のURLに出るだけで、出す範囲は広がらない |

## 3. 本文の記法に足す行

固定ページの本文（`ParseForPages`）だけで読む。社内文書（`Parse`）とお知らせ・カタログ（プレーンテキスト）は変えない。前置きは今のLPの部品（`ヒーロー: `・`ボタン: `・`カード: `）に揃え、日本語の名前・半角のコロン・半角スペース1つ。`\:` と書けばただの文字になる。条件に当たらない行は段落の行で、入力の文字は落とさない。判定は1行ずつで、後ろへの探索を足さない（読む時間は入力の長さに比例する）。

### 3.1 判定の順番（`richtext.md` の2節の表に足す行。レビュー用の案）

| 順 | 条件 | 種類 | 今のブロック |
|---|---|---|---|
| 5.9 | `質問: ` で始まり、後ろに空白以外の文字がある | 質問 | 直前が答えの済んだ質問の並びで、12問未満なら続く。それ以外は閉じて新しい並び |
| 5.10 | `答え: ` で始まり、後ろに空白以外の文字があり、**直前の行が質問の行** | 答え | 続く（質問に結ぶ） |
| 5.11 | `お知らせ: ` で始まり、後ろが3.3節の形 | お知らせの一覧 | 閉じる |
| 5.12 | 行全体が `お問い合わせ: ` と、後ろに空白以外の文字 | お問い合わせのボタン | 閉じる |
| 5.13 | `引用: ` で始まり、後ろに空白以外の文字がある | 引用 | 閉じる |
| 5.14 | `帯: ` で始まり、記号の `\|` がちょうど1つで、前後が空でない | 締めの帯 | 閉じて、新しい帯。直後の（空行をはさまない）ボタンの行は帯のボタン（3つまで） |
| 5.15 | `手順: ` で始まり、記号の `\|` がちょうど1つで、前後が空でない | 手順 | 直前が手順の並びで、12件未満なら続く。それ以外は閉じて新しい並び |
| 5.16 | `目次` だけの行（前後の空白を除いて） | 目次 | 閉じる |

- 質問の行は、**次の行が答えの行のときだけ**質問になる。答えが続かなければ段落の行として扱い、文字を落とさない。判定は「次の行」を1行だけ見る（今の表の行と同じ先読み）。答えの行も、直前が質問の行でなければ段落の行。
- 答えは1行だけ（段落1つ）。複数の段落の答えは扱わない。
- 見出しの飛び先（3.8節）は、見出しの行（順2）の読み方を変える。

### 3.2 よくある質問

```
質問: JavaScriptは必要ですか？
答え: いいえ、不要です。
```

- 描き方: 並びを `div.faq-list` に、1問を `details.faq-item` に、`summary` に質問、`div.faq-answer` の `p` に答え。開閉は標準の `<details>`（JSなし）。
- 質問と答えの文字の並びは段落と同じ読み方（強調・リンク）。

### 3.3 最新のお知らせ

```
お知らせ: 3
お知らせ: イベント | 3
```

- 形: `お知らせ: ` の後ろが、件数だけか、`カテゴリの名前 | 件数`。件数は半角数字で1〜10。それ以外は段落の行。
- カテゴリは**名前**で書く（利用者の決定、2026-11-26）。名前を変えた・消したカテゴリは、何も出さない（下の警告で気づかせる）。
- 出す記事: お知らせの公開の一覧と同じ条件（状態と公開日時。NEWS-INV-16）で、新しい順にN件。
- 描き方: `ul` に日付（`time`）と題名（記事へのリンク）。最後に「お知らせの一覧へ」のリンク（カテゴリありなら `/news?category=番号`）。記事が0件なら、「お知らせはまだありません。」を出す。
- お知らせの機能が無いサイトでは何も出さない。
- 警告: カテゴリの名前が見つからない・お知らせの機能が無いときは、プレビューと編集の画面に警告を出す（公開ページには出さない）。MCPの保存の確認の文にも出す。

### 3.4 お問い合わせのボタン

```
お問い合わせ: お問い合わせフォームを開く
```

- 行き先は今の `ContactLink`（お問い合わせ機能の `/contact` か、`CONTACT_FORM_URL` の外部フォーム）。書く人はURLを書かない。
- 描き方: `a.btn.btn-primary`。外部フォームなら、紹介サイトのトップと同じく新しいタブで開き（`rel="noopener noreferrer"`）、ボタンの文の後に「（新しいタブで開きます）」を足す。本文の他のリンクは同じタブのまま。
- 行き先が無いサイトでは何も出さず、プレビューと編集の画面に警告を出す。

### 3.5 引用・お客様の声

```
引用: 説明が丁寧で、安心して頼めました。 | 小売業 Aさん
```

- 形: `引用: 本文` か、`引用: 本文 | 出典`（記号の `|` が1つなら後ろが出典）。
- 描き方: `figure.quote` の中に `blockquote` の `p`、出典があれば `figcaption`。規則は `style.css` に足す。

### 3.6 締めの帯

```
帯: まず手元で動かしてみる | リポジトリを取得し、make run で起動できます。
ボタン: [GitHubで入手する](https://github.com/hideshi/minimal-web-kit)
```

- 描き方: `section.cta-banner` に `h2`（前に `##` の見出しがあれば `h3`。カードと同じ決め方）、`p`、ボタンがあれば `div.cta-actions`。

### 3.7 手順の並び

```
手順: 要件を確かめる | 保存するデータと増える依存を確かめます。
手順: 同梱機能とGoで作る | 必要な機能をコマンドで組み込みます。
```

- 描き方: `ol.step-list`（`role="list"`）に `li.step-item`、`div.step-number` に「STEP n」、`h3.step-title`（前に `##` が無ければ `h2`）、`p.step-content`。

### 3.8 見出しの飛び先と目次

```
## 特長 {#features}
目次
```

- 見出しの行の末尾が ` {#名前}` なら、その名前を見出しの `id` にする。名前は英小文字・数字・ハイフンで1〜40文字（スラッグと同じ形）。形に合わなければ、今と同じく見出しの文字の一部。
- 同じ名前が2度出たら、2つ目からは `id` を付けない（保存の検査で警告する）。名前は、Coreが使う `id`（`main` 等。レイアウトの中にある全部）と重ならないものだけ許す。
- リンクのURLに `#名前`（名前は同じ形）を足す（`richtext.md` の5節）。`/#名前`・`/パス#名前` は今の「サイト内」に入る。
- 目次: `目次` の行は、本文の中の飛び先を持つ `h2` を順に並べた `nav.page-contents`（`aria-label="このページの目次"`）。飛び先を持つ `h2` が無ければ何も出さない。

## 4. お知らせとお問い合わせを固定ページに渡す

固定ページはお知らせの機能を読み込まない（機能どうしは互いに依存しない）。今のお問い合わせの行き先（`ContactLinkFeature`・`ContactLinkConsumer`）と同じ形で、Coreの口を通して渡す。

- `features.NewsListFeature`（お知らせが実装）: `LatestPublished(ctx, category string, n int) (items []web.NewsSummary, found bool, err error)`。`category` が空なら全部。`found` はカテゴリの名前があったか。
- `features.NewsListConsumer`（固定ページが実装）: 起動時に上の関数を受け取る。受け取らなければ、お知らせの一覧は出さない。
- お問い合わせ: 固定ページが `ContactLinkConsumer` を実装する。

公開ページは要求のたびにDBから読む（今の固定ページと同じく、公開キャッシュは使わない）。お知らせの公開・非公開は、次の表示から反映される。

## 5. トップに使うページ

- 環境変数 `HOME_PAGE_SLUG` にスラッグを書く（利用者の決定、2026-11-26）。空なら今のまま（Siteのトップか、Baseのトップ）。形が正しくなければ起動を止める。固定ページの機能が無ければ起動を止める。
- `GET /` は、そのスラッグの固定ページが公開中（予約の時刻を過ぎている）なら固定ページを返す。無い・下書き・予約中・読み取りの失敗のときは、今のトップ（`CustomRootFeature` かBase）を返す。読み取りの失敗は記録する。
- `CanonicalPath` は `/`。`/{スラッグ}` は `/` へ転送（301。中身が一つのURLに決まるため）。`sitemap.xml` には `/` だけを載せ、`/{スラッグ}` を載せない。ナビに出す順があっても、ナビの行き先は `/`。
- OGPの画像は今の固定ページの作り方（`/ogp/pages/{名前}.png`）のまま。
- 静的な書き出し（`export-static`）は、固定ページの機能があると今も拒否するので、変えない。
- 管理画面とMCPの確認の文に、「このページはトップページです」と出す。

## 7. 試験

- 記法: 3.1節の表の行ごとに、当たる例・当たらない例（段落に戻ること、文字が落ちないこと）、上限（質問12・手順12・件数10）、`\:`、先読み（答えの無い質問）。長い入力で時間が比例すること（今の速さの試験に足す）。
- 描き方: テンプレートの検査に新しいクラスを足す。`details`・`nav`・`figure` の構造、外部フォームの新しいタブと文。
- お知らせ: 下書き・予約中・別のカテゴリの記事を出さない、名前が無いと0件で警告、機能が無いと何も出さない。
- トップ: 公開中なら `/` に出る、下書き・予約中・無いと今のトップ、`/{スラッグ}` の301、`sitemap.xml`、`CanonicalPath`、起動の検査（形・機能なし）。
- Cookie: `/` を固定ページで返しても、セッションCookieを発行・照合しない（今の公開ページの試験を `/` にも当てる）。
- 確かめ: 紹介サイトのトップを、新しい部品だけで書き直した本文を試験の見本に置き、プレビューで崩れないことを画面の写しで見る（`test/browser`）。
