# お知らせの LINE への一斉送信 実装計画

状態: 2026-11-17、利用者が範囲（一斉送信だけ、題名と URL だけ、サイト管理者以上、1記事に1回だけ、毎回通知する）と、承認境界2（送った記録の表）・3（`api.line.me` への送信）を承認した。計画のレビューの前。

対象の時点: `150b100` から。

正本: 実装のときに [domain/news.md](../domain/news.md) へ移す。

## 1. 目的と範囲

見込み顧客や顧客が LINE 公式アカウントの友だちになっているサイトで、新しいお知らせを、管理画面から友だち全員へ知らせられるようにする。知らせるだけにして、読むのはサイトの記事のページで行う。

- 送るのは、サイト名・記事の題名・記事の URL のテキスト1通だけ。本文や冒頭は送らない。
- 送るのは、管理者がボタンを押したときだけ。公開の操作や予約公開の時刻に合わせて自動では送らない（予約公開の記事は、公開日時を過ぎると操作なしで公開側に出るため、自動で送るには裏で動く仕組みが要る）。
- 1つの記事は1回だけ送れる。送った記事は、二度と送れない。
- 設定しなければ、ボタンを出さず、外へ通信しない。

作らないもの: 個別の送信（Push）、友だちの識別子の保存、Webhook の受信、リッチメニューの設定、絞り込みの配信（Narrowcast）、画像や Flex Message、通知の音を消す選択、確認の画面での残りの通数・友だちの数の表示、お知らせ以外の機能（カタログ・固定ページ）からの送信、AIエージェント（MCP）からの送信、送信の予約。個別のやり取りは、LINE 公式アカウントの管理画面かアプリのチャットで行う（無料の通数を使わない）。

## 2. 画面と流れ

| 画面 | 経路 | 型 | 内容 |
|---|---|---|---|
| お知らせの編集 | `GET /admin/news/{id}`（既存） | 作成・編集 | 公開などの別操作の並びに「LINE で知らせる」のリンクを足す。送った記事では、リンクの代わりに「LINE で知らせた日時」を出す |
| LINE での知らせの確認 | `GET /admin/news/{id}/line` | 削除の確認と同じ形 | 送る文面をそのまま見せ、友だち全員に届くこと、取り消せないこと、通数を使うこと、1回だけ送れることを説明する |
| 送信 | `POST /admin/news/{id}/line` | — | 送って、編集の画面へ戻し、結果を `notice`・`error` で見せる |

- 守り: 既存のお知らせの管理画面と同じ `f.admin.Page`・`f.admin.Form`（サイト管理者以上）。
- リンクと送信は、記事が公開側に出ているとき（公開の状態で、公開日時を過ぎている。`NEWS-INV-1` と同じ条件）だけ許す。送信のときにもう一度確かめる。
- 確認の画面の型は、取り消せない操作の確認なので「削除の確認」の構成に合わせる。`test/admin_ui_test.go` がこの型を削除だけに限っていないかを、実装の前に確かめる。限っていれば、型を足すか、名前を広げるかを `docs/components.md` で決める。

送る文面（例）:

```
{SITE_NAME}のお知らせ
{題名}
{SITE_URL}/news/{id}
```

題名は200文字まで（`maxTitleRunes`）なので、LINE の上限（UTF-16 の単位で5,000）には届かない。それでも、作った文面の UTF-16 の長さを確かめ、超えたら送らない。

## 3. 送信の手順と二重送信の防止

送った記録を、記事ごとに1行持つ（4節）。状態は「送信中」と「送信済み」の2つ。

1. 1つのトランザクションで、記事の記録を読む。
   - 無ければ、新しい再送の鍵（`crypto/rand` の UUID v4）と、そのときの文面を、状態「送信中」で書く。
   - 「送信済み」なら、送らずに「送信済み」と見せる。
   - 「送信中」なら、保存した鍵と文面を使う（前回の結果が分からなかった、または失敗した）。ただし、最初の送信から23時間を過ぎていたら送らない（6節）。
2. トランザクションの外で、`POST https://api.line.me/v2/bot/message/broadcast` に、保存した文面と `X-Line-Retry-Key: {鍵}` を送る。
3. 結果で分ける。

| 応答 | 意味 | 記録 | 画面 |
|---|---|---|---|
| 200 | 受け付けた | 送信済み | 送りました |
| 409 で `x-line-accepted-request-id` あり | 同じ鍵の要求を受け付け済み | 送信済み | 送りました |
| 429 | 回数か月の通数の上限 | 送信中のまま | 上限に当たった。時間をおくか、LINE の管理画面で通数を確かめる |
| 400・401・403 | 文面かトークンの誤り | 送信中のまま | 設定を確かめる（運用者向けの案内） |
| 5xx・時間切れ・接続の失敗 | 受け付けたか分からない | 送信中のまま | 結果が分からない。もう一度押すと、同じ鍵で送り直す（重ならない） |

- 送り直しは、管理者がもう一度押したときだけ。自動では送り直さない。
- 2人が同時に押しても、同じ鍵を使うので、LINE の側で1回に絞られる。
- 送り直しでは、文面を作り直さない（LINE は送り直しで中身を変えないよう求めている）。題名を後から直しても、送る文面は最初のまま。

## 4. 保存するもの（承認境界2）

表 `news_line_broadcasts` を足す。

| 列 | 中身 |
|---|---|
| `post_id` | 記事の番号。主キー。`news_posts(id)` を参照し、記事を消したら一緒に消す |
| `retry_key` | 再送の鍵（UUID） |
| `message` | 送る文面（公開済みの題名と URL だけ） |
| `state` | `sending` か `sent` |
| `first_tried_at` | 最初に送ろうとした日時 |
| `sent_at` | 送信済みになった日時。送信中は NULL |

- 個人の情報は入らない。友だちの情報は LINE が持ち、サイトは受け取らない。
- 保持: 記事を消すまで。
- `docs/data-inventory.md` に、この表と、トークンのファイル（DBの外のファイル）を足す。

## 5. 設定とトークン（承認境界3）

- `LINE_CHANNEL_TOKEN_FILE`: チャネルアクセストークンを1行で書いたファイル。通知の Webhook と同じ `federation.SecretFile`（通常のファイル、所有者だけが読める）で読む。空白・改行・制御文字が中に混ざっていたら起動を止める。
- 有効にするときは、`SITE_URL`（記事の絶対 URL を作るため）と `SITE_NAME` を必須にする。
- トークンは、LINE Developers コンソールで発行する長期のチャネルアクセストークンを使う。期限が無く、いつでも取り消せる。発行し直すと前のものは使えなくなる。期限付き（v2.1、短期、ステートレス）は、更新の仕組みか鍵の組が要り、送る回数の少ないこの用途には重い。
- 送信は `federation.Client` を使う。許す URL は `https://api.line.me/v2/bot/message/broadcast` の1つだけ。転送に従わない。タイムアウトは10秒。応答の本文は小さい上限で読む。
- ログには、トークン、`Authorization` の見出し、応答の本文、`err.Error()` を出さない。`news line broadcast` に、記事の番号と結果の分類（`sent`・`already_accepted`・`rate_limited`・`rejected`・`unknown`）だけを付ける。

## 6. 確かめた公式の資料（2026-11-17）

| 項目 | 確かめたこと | 出典 |
|---|---|---|
| 送り先と見出し | `POST https://api.line.me/v2/bot/message/broadcast`。`Content-Type: application/json`、`Authorization: Bearer {トークン}`。`X-Line-Retry-Key` は任意 | Messaging API リファレンス（Send broadcast message） |
| 中身 | `messages` は5つまで。`notificationDisabled` の既定は `false`（通知する）。送り先の指定は無く、友だち全員に届く | 同上 |
| 回数の上限 | 1つのチャネルで1時間に60回。超えると 429 | 同上 |
| 再送の鍵 | 16進の UUID を送る側が作る。最初の要求から24時間有効。受け付け済みなら 409 と `x-line-accepted-request-id`。中身と宛先を変えずに送り直す | Retrying an API request |
| 通数 | 送った相手の人数で数える。1回の要求の吹き出しの数は数に影響しない。一斉送信は数える対象。ブロックした人など受け取れない人は数えない。月の上限を超えると 429 | Messaging API pricing |
| 文字数 | テキストは5,000文字まで。UTF-16 の単位で数え、サロゲートペアや一部の絵文字は2文字以上になる | リファレンス（Text message） |
| トークン | 4種類（v2.1 は30日まで、ステートレスは15分で取り消せない、短期は30日、長期は期限なしでコンソールから発行し取り消せる）。どれを勧めるかは書かれていない | Channel access token |

確かめられなかったこと: 月の通数が足りないときに、一部の友だちにだけ届くのか、全く届かないのか。23時間の余白は、24時間の期限の数え方（LINE の側の時刻）とのずれを見込んだもの。

## 7. 不変条件（案）

番号は `NEWS-INV-19` から。守る場所は、実装の後に識別子で埋める。

| 番号 | 条件 |
|---|---|
| NEWS-INV-19 | LINE へ送るのは、公開側に出ている記事だけ。送る文面は、サイト名・題名・記事の URL だけで作る |
| NEWS-INV-20 | 1つの記事について、送信済みになった後は送らない。送り直しは、最初に作った鍵と文面のままで、最初の送信から23時間の間だけ |
| NEWS-INV-21 | 送れるのはサイト管理者以上。AIエージェント（MCP）のツールからは送れない |
| NEWS-INV-22 | 送り先は `https://api.line.me/v2/bot/message/broadcast` だけで、転送に従わない。トークンは所有者だけが読めるファイルから読み、トークン・応答の本文・エラーの文をログと画面に出さない |
| NEWS-INV-23 | 設定しなければ、ボタンを出さず、外へ通信しない |

## 8. 試験

- 下書き・予約公開の記事では、リンクが出ず、送信が断られる（INV-19）。
- 文面にサイト名・題名・URL 以外が入らない。本文をカナリアにして確かめる（INV-19）。
- 送信済みの記事は送らない。送信中なら同じ鍵と文面で送る。題名を直した後も文面が変わらない。23時間を過ぎた送信中は送らない（INV-20）。
- 200・409・429・400・401・5xx・時間切れのそれぞれで、記録の状態と画面の文言（INV-20、3節の表）。
- 一般ユーザーは断られる。MCP のツールの一覧に送信が無い（INV-21）。
- 別の URL・転送（302）を断る。権限の緩いトークンのファイルを断る。ログに `Authorization` とトークンのカナリアが出ない（INV-22、`test/` のログ非漏洩カナリア）。
- 未設定で、リンクが出ず、HTTP の通信が起きない。有効なのに `SITE_URL` か `SITE_NAME` が無ければ起動を止める（INV-23）。
- LINE の API は `httptest` の偽の送り先で差し替える。実際の LINE には試験から送らない。
- 守りを外して、対応する試験が落ちることを確かめる。
