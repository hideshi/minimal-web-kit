# カタログのタグ選択 UI 比較計画

状態: 比較試作の範囲を具体化。Alpine.jsの取得・追加・CSP変更は承認待ち。
本体の仕様は [domain/catalog.md](domain/catalog.md)。この試作だけで採用を決定しない。

## 比較するもの

| 版 | UI | 技術 |
|---|---|---|
| 基準 | 現行と同じチェックボックス一覧、新規タグ名の入力 | 標準HTML |
| 試作 | タグ名による即時絞り込み、選択済みの一覧、個別の解除。新規タグ名の入力は基準と同じ | 標準のチェックボックス・ボタンとAlpine.js CSPビルド |

架空の同じタグを10・50・200件で用意する。検索で選択済みタグを隠しても選択を失わず、合計20個の上限を守る。複雑な独自コンボボックスは作らず、チェックボックスの意味とキーボード操作を保つ。
Alpine.jsが動かない場合は基準の一覧に戻す。検索欄は検索可能な状態になったときだけ表示し、選択値は両版とも同じタグIDの集合として確認する。新規タグを架空データへ永続追加する処理は作らない。

## 試作の隔離

- 実行入口案は `cmd/catalog-ui-compare`、補助ファイルは `experiments/catalog-tags/`。明示的なコマンドで起動する比較専用サーバーとし、通常のサーバー・Feature登録・公開サイトには組み込まない。
- 待受は127.0.0.1の空きポートだけ。実際のDB・アカウント・カタログは読まず、架空データと画面内の一時状態だけを使う。Cookie・localStorage・sessionStorage・操作履歴は作らない。
- CSSは既存のstyle.cssを再利用し、必要なクラスだけ同じファイルへ追加する。新しいCSSファイル、インラインstyle、インラインscriptは作らない。
- JS追加案は `experiments/catalog-tags/static/alpine-csp.min.js` と `tags.js` の2本。固定版・取得元・ライセンス・ハッシュを記録する。実行時は自サイトからだけ配信する。
- 比較専用のAlpine版だけscript-srcをselfにし、基準版はnone。他のCSP指示は緩和せず、unsafe-eval/unsafe-inlineは許可しない。
- AGENTS.mdとJSの機械的な許可検査には比較専用の2本と画面だけを明示する。本体の管理画面に読み込める例外にはしない。公式資料照合とファイル取得は承認後に行う。

## 同じ条件で行う操作

1. 指定した3つのタグを見つけて選ぶ。
2. 1つを解除し、別のタグに変更する。
3. 同名に近いタグを識別し、選択内容を見直す。
4. 検索条件を変えても選択済みの集合が変わらないことを確認する。
5. キーボードだけで同じ作業を行い、20個の上限に達した場合の説明と操作を確認する。
6. JavaScript無効、320px幅、文字200%でも同じ結果を得られるか確認する。

操作の回数、探しやすさ、選択を見失う場面、誤操作、フォーカス、読み上げ通知を記録する。自動操作の経過時間を人間の使いやすさの指標として扱わない。利用者が両画面で同じ操作を試せるようにし、読み上げソフトで未確認の項目は未確認とする。
UIの結果とは別に、JSの転送量、追加コード、CSPへの適合、保守負担も記録する。検索や選択済み表示の効果と、Alpineというライブラリを選ぶ理由を区別する。標準版で十分、または別の軽い改善が適切という結論も認める。

## 承認が必要な範囲

- 境界3: 公式資料の確認と固定版Alpine CSPビルドの取得のための外部通信。実行時の外部通信は追加しない。
- 境界4: 比較専用JS2本と、同画面だけの規約・検査の例外追加。
- 境界5: 比較専用のAlpine版画面だけのscript-src self。
- 入力は既存のタグ選択・新規タグ名と、比較版の一時的な検索欄。実データへの保存、DB列、Cookie、セッション項目は追加しない。

本体への採用、実際の管理画面でのCSP変更、画像アップロード、本番公開はこの試作の承認範囲に含めない。
