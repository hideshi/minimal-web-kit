# カタログのタグ選択 UI 比較計画

状態: 2026-10-26、利用者が比較専用のJS2本・取得時の通信・Alpine版のみのCSP変更を承認。比較試作を実装。検証結果は末尾に記載。
本体の仕様は [domain/catalog.md](domain/catalog.md)。この試作だけで採用を決定しない。

試作のコードは配布するひな形に含めないため、2026-10-26に main から外し、`experiment/catalog-tags` ブランチへ移した（利用者の判断）。この文書は比較の記録として main に残す。試作を動かすときは、そのブランチで `go run ./cmd/catalog-ui-compare` を実行する。以下の「試作の隔離」「承認が必要な範囲」は、試作が main にあった時点の記述。

## 比較するもの

| 版 | UI | 技術 |
|---|---|---|
| 基準 | 現行と同じチェックボックス一覧、新規タグ名の入力 | 標準HTML |
| 試作 | タグ名による即時絞り込み、選択済みの一覧、個別の解除。新規タグ名の入力は基準と同じ | 標準のチェックボックス・ボタンとAlpine.js CSPビルド |
| 試作2 | 入力欄にフォーカスすると候補の一覧が開き、入力で絞り込むコンボボックス。選択済みの一覧と個別の解除は試作と同じ | WAI-ARIAのcombobox＋listboxとAlpine.js CSPビルド |

架空の同じタグを10・50・200件で用意する。検索で選択済みタグを隠しても選択を失わず、合計20個の上限を守る。試作は独自のコンボボックスを作らず、チェックボックスの意味とキーボード操作を保つ。
試作2は、一般的なタグ入力の形と比べたいという利用者の依頼（2026-10-26）で追加した。状態（開閉・今いる候補・入力・選択・変換中）が多く、Alpineの利点が出やすい部品として比べる。JSは承認済みの2本（`tags.js` への追加）に収め、CSPも試作と同じ範囲にする。
Alpine.jsが動かない場合は基準の一覧に戻す。検索欄は検索可能な状態になったときだけ表示し、選択値は両版とも同じタグIDの集合として確認する。新規タグを架空データへ永続追加する処理は作らない。

## 試作の隔離

- 実行入口案は `cmd/catalog-ui-compare`、補助ファイルは `experiments/catalog-tags/`。明示的なコマンドで起動する比較専用サーバーとし、通常のサーバー・Feature登録・公開サイトには組み込まない。
- 待受は127.0.0.1の空きポートだけ。実際のDB・アカウント・カタログは読まず、架空データと画面内の一時状態だけを使う。Cookie・localStorage・sessionStorage・操作履歴は作らない。
- CSSは既存のstyle.cssを再利用し、必要なクラスだけ同じファイルへ追加する。新しいCSSファイル、インラインstyle、インラインscriptは作らない。
- JS追加案は `experiments/catalog-tags/static/alpine-csp.min.js` と `tags.js` の2本。固定版・取得元・ライセンス・ハッシュを記録する。実行時は自サイトからだけ配信する。
- 比較専用のAlpine版だけscript-srcをselfにし、基準版はnone。他のCSP指示は緩和せず、unsafe-eval/unsafe-inlineは許可しない。
- AGENTS.mdとJSの機械的な許可検査には比較専用の2本と画面だけを明示する。本体の管理画面に読み込める例外にはしない。公式資料照合とファイル取得は承認後に行う。

## 同じ条件で行う操作

1. 指定した3つのタグを見つけて選ぶ。
2. 1つを解除し、別のタグに変更する。
3. 同名に近いタグを識別し、選択内容を見直す。
4. 検索条件を変えても選択済みの集合が変わらないことを確認する。
5. キーボードだけで同じ作業を行い、20個の上限に達した場合の説明と操作を確認する。
6. JavaScript無効、320px幅、文字200%でも同じ結果を得られるか確認する。

操作の回数、探しやすさ、選択を見失う場面、誤操作、フォーカス、読み上げ通知を記録する。自動操作の経過時間を人間の使いやすさの指標として扱わない。利用者が両画面で同じ操作を試せるようにし、読み上げソフトで未確認の項目は未確認とする。
UIの結果とは別に、JSの転送量、追加コード、CSPへの適合、保守負担も記録する。検索や選択済み表示の効果と、Alpineというライブラリを選ぶ理由を区別する。標準版で十分、または別の軽い改善が適切という結論も認める。

## 承認が必要な範囲

- 境界3: 公式資料の確認と固定版Alpine CSPビルドの取得のための外部通信。実行時の外部通信は追加しない。
- 境界4: 比較専用JS2本と、同画面だけの規約・検査の例外追加。
- 境界5: 比較専用のAlpine版画面だけのscript-src self。
- 入力は既存のタグ選択・新規タグ名と、比較版の一時的な検索欄。実データへの保存、DB列、Cookie、セッション項目は追加しない。

本体への採用、実際の管理画面でのCSP変更、画像アップロード、本番公開はこの試作の承認範囲に含めない。

## 検証結果（2026-10-26、自動操作による動作確認）

人による操作感の比較ではなく、試作が比較に使える状態かの確認。

| 項目 | 結果 |
|---|---|
| 10・50・200件での絞り込み・選択・解除・確認送信 | 両版とも期待どおり。検索で隠れた選択も送信される |
| Spaceキーでの選択、20個の上限 | Alpine版は上限で未選択項目を無効化。新規タグを含む上限は両版ともサーバーで拒否 |
| 選択済みボタンで解除した後のフォーカス | 不具合を修正済み。表示中なら該当のチェックボックス、隠れていれば検索欄へ移す |
| JSの読込失敗（tags.jsだけ・Alpineだけ・両方） | いずれも検索欄を出さず、標準の一覧から同じ結果を送信できる |
| CSP | Alpine版はscript-src selfで違反なし。標準版はnoneのまま |
| 追加のJS | Alpine CSPビルド72,242バイト＋tags.js約2.2KB。標準版は0 |

### 試作2（コンボボックス）

| 項目 | 結果 |
|---|---|
| フォーカスで開く・入力で絞り込む・↑↓とEnterで選択・Escで閉じる・空欄のBackspaceで最後を解除 | 期待どおり。Enterはフォームを送信しない |
| 候補のクリック | 入力欄からフォーカスが外れず、続けて選べる |
| 日本語入力の変換中のEnter | 候補を選ばない |
| 20個の上限 | 未選択の候補を `aria-disabled` にし、選ぼうとすると上限を通知する |
| 確認送信 | 他の版と同じタグIDの集合を送信できる |
| 幅320px | 横スクロールなし。候補の一覧は枠の中でスクロールする |
| JSの読込失敗（tags.jsだけ・Alpineだけ・JS無効） | 入力欄を出さず、全件のチェックボックスから送信できる |
| 追加のJS | tags.jsが約7KBに増加。Alpine本体は共通 |

### 試作3（素のJSのコンボボックス）と技術の選定

2026-10-26、3段目の技術を検討した。キットは依存の最小化をUIの豊かさより優先し、複雑なUIはReact・Vue等のフロントエンドフレームワークへ案内する（[ui-guidelines.md](ui-guidelines.md)）。この線引きでは3段目の部品は少数・小規模にとどまるため、状態を画面に揃える仕組み（Alpine）の利点は小さい。

| 候補 | 配布物の大きさ（未圧縮） | 評価 |
|---|---|---|
| Alpine.js CSPビルド 3.17.5 | 72,242バイト | 状態と画面を自動で揃える。CSPビルドでは処理をJSファイルの名前付きメソッドに置くため、HTMLに書ける手軽さは活きない |
| Stimulus 3.2.2 | 88,680バイト（公式の配布物に圧縮版なし） | HTMLに名前だけ書く設計はキットに合う。最新版は2023-08で以後リリースなし（リポジトリは保守され、2026-06の修正は未リリース）。`eval` を使わず、公開されたセキュリティ勧告は0件。キットのサーバーは応答を圧縮しないため、Alpineより重い |
| Lit | 未計測 | 描画がJSに移り、Shadow DOMがCSS1本の規約とぶつかるため対象外 |
| 素のJS | 部品の分だけ | 依存なし。htmxで差し替えた部分は `htmx:load` で付け直す |

利用者の判断で、素のJSを採用する方向とした。比較のため、Alpine版の試作2と同じ操作・送信内容の試作3（`combobox.js` 1本、約8KB・211行）を作った。Alpine版の該当部分は約5.7KB・137行に、HTML側の `x-` 属性が加わる。試作2と同じ自動操作（キー操作、クリック、日本語入力の変換中のEnter、20個の上限、確認送信、幅320px、JS無効・読込失敗）で期待どおりに動き、エラー・CSP違反はなかった。

未確認: 読み上げソフトでの通知・操作、320px幅・文字200%での目視、利用者による両版の操作感の比較。採否はこれらの結果と保守負担を合わせて決める。
