# お問い合わせ機能 実装計画

状態: 2026-10-29、計画の段階。利用者の依頼「サイトの中にお問い合わせ窓口を持ち、IPアドレスを記録せず、外部のCAPTCHAを使わずにスパムを防ぐ」による。外部レビュー（Fable）の指摘を本文に反映した（要点は12節）。承認境界2（保存データの追加）に当たるため、11節の決定と承認を得てから実装する。

## 1. 目的と範囲

サイトの中にお問い合わせのフォーム（`/contact`）を置き、届いた内容を管理画面の受信箱で読めるようにする。今は外部のフォームサービスのURL（`CONTACT_FORM_URL`）へのリンクだけで、問い合わせの内容がその事業者に渡る。自前で持つことで、何を・どこに・いつまで保存するかを運営者が説明できるようにする。

- 新しい同梱機能 `contact`（`features/contact/`、`make add-contact`・`remove-contact`）。管理者認証（`features/auth`）を使う。お知らせ・カタログとは独立。`cmd/kit` にバンドルの印を足し、お問い合わせが有効な間は `remove-auth` を拒否する（カタログと同じ扱い）。
- **メールは送らない**。届いたことは管理画面で確かめる（外部通信を増やさない。承認境界3に当たらない）。
- **IPアドレス・User-Agent・Cookieを使わない、記録しない**。公開のフォームはセッションを作らない。
- **外部のCAPTCHA・JavaScriptを使わない**（承認境界3・4に当たらない）。
- 作らないもの: 返信機能（運営者は、本人が書いた返信先へ自分で連絡する）、添付ファイル、種別ごとの振り分け、自動返信、受信の通知。

## 2. 受け取る情報（承認境界2）

| 項目 | 必須 | 上限 | 目的 |
|---|---|---|---|
| お問い合わせ内容 | 必須 | 2,000文字 | 問い合わせへの対応 |
| お名前 | 任意 | 50文字 | 返信のときの呼び方 |
| 返信先（メールアドレス・電話番号など） | 任意 | 200文字 | 返信が必要な場合の連絡先。形式は検査しない（メール・電話・SNS等、本人が選ぶ） |

- 返信が要らない人は、内容だけで送れる。画面で「返信が必要な場合だけ書いてください」と案内する。
- 保存するのは上の3つと、受付日時・状態（未読・既読・スパム）だけ。IPアドレス・User-Agent・送信元のページは保存しない。
- **保持期間**: 受付から90日で、状態（未読・既読・スパム）に関係なく自動で削除する（`PurgeFeature`。起動時と1時間ごと）。管理画面からも個別・まとめて削除できる。期間は環境変数 `CONTACT_RETENTION_DAYS`（1〜365、既定90。範囲外・数字でない値は起動を止める）で変えられる。
- **バックアップ**: 削除した後も、削除前のバックアップの複製には、その複製の保持期間のあいだ残る。プライバシーポリシーには「保持期間＋バックアップの保持期間」を合わせて書く（雛形は運営者が自分の運用に合わせて書き換える。例: 紹介サイトはVPSに14日・手元に3か月の複製を残すため、最長で約半年）。
- `docs/data-inventory.md` の1節（氏名・連絡先を一切取得しない）に「お問い合わせ機能を有効にした場合を除く」の但し書きを足し、お問い合わせの節を新しく書く。
- プライバシーポリシーには `PrivacyFeature` で表を載せる。Coreの「お問い合わせでお預かりする情報（外部フォーム）」の節は、外部フォーム（`CONTACT_FORM_URL`）を使う構成のときだけ出す（3節の口で渡す）。

## 3. 公開のフォーム

- `GET /contact`: フォーム。`POST /contact`: 送信。保存に成功したら、既存の `notice` の仕組み（`/contact?notice=sent`）で完了の文を出す（再送信を防ぐ）。
- 独立経路（`IsolatedRoutesFeature`）。Cookieを発行せず、セッションを作らない。CSPは `script-src 'none'` のまま。`GET /contact` は応答ごとに違う値を含むため、`web.PublicCache` を使わず `Cache-Control: no-store` のままにする。
- 状態を変える `POST` は、`guard.SameOrigin`（`Sec-Fetch-Site: same-origin` と `Origin`）で他のサイトからの送信を拒否する。比べるオリジンは、管理者認証と同じ `AUTH_ORIGIN` を `guard.NormalizeOrigin` で読む（未設定なら開発用の既定の扱いに合わせる）。セッションが無いため、CSRFトークンの代わりに4節の署名つきのフォームの値を使う。`Sec-Fetch-Site` を送らない古いブラウザは送れない（管理画面と同じ割り切り）。
- 画面は部品（`field`）と、公開ページのレイアウト（Siteがあればそのヘッダー・フッター、無ければ自前のレイアウト。お知らせと同じ作り）で作る。入力の誤りは、その欄にエラーを出し、入力を残して400で返す。
- 本文・お名前・返信先は、管理画面でも文字として表示する。URLやメールアドレスを自動でリンクにしない（`mailto:` 等を作らない）。
- **Siteとの接続**: Siteは「他の機能があるか」で分岐せず、お問い合わせの行き先を申告する口（新しい任意のインターフェース。例: `ContactLinkFeature` が「行き先のURL・外部か」を返す）で受け取る。LPのボタンは、`/contact` のときは同じタブで開き、外部フォームの補足文（「新しいタブで開きます」等）を出さない。Coreのプライバシーポリシーの外部フォームの節も、この申告で出し分ける。ヘッダーの「お問い合わせ」（`/#contact`）はLPの節を指すため変えない。
- **`CONTACT_FORM_URL` と同時に有効にした場合は、起動時にエラーで止める**（受付の口が2つになり、説明が二重になるのを防ぐ。外部フォームを続けたい運営者は、この機能を有効にしない）。

## 4. スパム対策

単純なボットをアプリで落とし、連打は前段で抑え、それでも漏れた分は全体の上限で受信箱を守る。完全には防げない（人が手で書く宣伝は防げない）ことを文書に書く。**人の問い合わせを黙って捨てない**ことを優先し、「受け付けたふり」は、人が引っかかる余地がほとんど無い2つ（ハニーポット・3秒未満）だけに使う。

### 4.1 アプリの中（IP・外部サービスを使わない）

| 対策 | 仕組み | 判定したとき |
|---|---|---|
| 見えない入力欄（ハニーポット） | 人には見えない入力欄を1つ置く。CSSで画面外に出し、`aria-hidden="true"`・`tabindex="-1"`・`autocomplete="off"`、ラベルは「この欄は空のままにしてください」。名前は、ブラウザの自動入力が反応しない意味の無いもの（`email`・`url`・`website`・`phone` 等にしない） | 受け付けたふり（完了の画面へ移す） |
| 署名つきのフォームの値 | `GET /contact` で、発行時刻と使い捨ての乱数を、サーバーの秘密鍵でHMAC-SHA256の署名をした値をフォームに埋め込む。秘密鍵は起動時に `crypto/rand` で作り、メモリにだけ置く（保存しない） | 署名が合わない・形式が違う: 400で「もう一度送信してください」、入力を残す |
| 送信までの時間 | 発行から3秒未満の送信は捨てる。1時間を過ぎた値は期限切れ | 3秒未満: 受け付けたふり。期限切れ: 400で「時間が経ったため、もう一度送信してください」、入力を残す |
| 使い捨て | **保存に成功したときだけ**、その乱数をメモリに1時間覚え、同じ値の2回目は保存しない（1つの値での連続送信を防ぐ）。記録の数は全体の受付上限（1日100件）以下に収まる | 400で「もう一度送信してください」、入力を残す（戻るボタンで古いフォームから送った人を黙って捨てない） |
| URLの数 | 内容のURL（`http://`・`https://`・`www.`）は2つまで | 内容の欄のエラー（400、「URLは2つまでにしてください」） |
| 全体の受付上限 | サイト全体で、1時間に20件・1日に100件まで。未読が500件を超えたら受け付けない。**数えるのは保存した件数だけ**で、DBの受付日時から数える（再起動に耐える。捨てた送信を数えないので、ボットが安く人を締め出せない） | 「現在、お問い合わせの受付を一時停止しています」（503、入力を残す） |

- **400で再表示するときは、期限内で署名が正しい元の値をそのまま埋め直す**（新しく発行し直すと、誤字を直してすぐ送った人が「3秒未満」で黙って捨てられるため）。期限切れ・署名の誤り・使用済みのときだけ、新しい値を発行する（その文言を読む時間で3秒は超える）。
- 判定の結果は、固定の分類（`saved`・`honeypot`・`too_fast`・`expired`・`bad_token`・`replayed`・`too_many_links`・`over_limit`）でログに1行出す。入力の中身は出さない。公開後に `honeypot`（人が誤って埋めていないか）と各分類の件数をログで確かめる。
- ハニーポットの欄は部品（`field`）で作れない（`aria-hidden`・`tabindex` を持たない）。テンプレートの検査（`TestTemplate_FormControlsUseComponents`）の許可リストに、理由つきで1つだけ足す。
- 再起動で秘密鍵と使い捨ての記録は消える。開いていたフォームは「もう一度送信してください」になる（入力は残る）。

### 4.2 前段（Cloudflare等）

キットの範囲外として、`docs/deploy.md` に推奨を書く。Cloudflareの無料プランのレート制限のルールは、1つだけ・条件はパスだけ（GETとPOSTを区別できない）・数える時間と止める時間は10秒（2026-10-29に公式の資料で確認）。条件を `/contact` で始まるパスに限り、「同じIPから10秒に5回まで」のようなルールを掛けると、連打を少し抑えられる。IPで判定するのは前段で、アプリはIPを受け取らない。

### 4.3 使わないもの

- CAPTCHA（Cloudflare Turnstile・reCAPTCHA等）: 外部のスクリプトとJavaScriptが要る（承認境界3・4）。上の対策で防げなくなったときの最後の手段として、文書に書くだけにする。
- JavaScriptでの計算による証明: JavaScriptが要り、本気のボットには効きにくい。
- IPアドレスごとの上限: IPを扱わない方針のため。前段に任せる。

## 5. 管理画面（受信箱）

| 画面 | 型 | 内容 |
|---|---|---|
| `GET /admin/contact` | 一覧 | `h1`「お問い合わせの管理」。未読の件数と「受付から90日で自動で削除します」を見出しの下に出す。表は受付日時（詳細へのリンク）・状態・お名前（無ければ「（無記名）」）・内容の冒頭30文字。新しい順、20件ずつ。空なら「お問い合わせはまだありません。」。スパムがあれば「スパムをまとめて削除する」へのリンク |
| `GET /admin/contact/{id}` | 詳細 | `h1`「お問い合わせ: お名前」（無記名は「お問い合わせ: （無記名）」）。全文（段落で表示）・返信先・受付日時・状態。操作は「既読にする」「未読に戻す」「スパムにする」（それぞれPOST）と、削除のリンク |
| `GET /admin/contact/{id}/delete` | 削除の確認 | 1件の削除 |
| `GET /admin/contact/spam/delete` | 削除の確認 | スパムの印を付けたものを、まとめて削除。0件なら一覧へ転送し「スパムはありません」と出す |

- **GETで状態を変えない**（開いただけで既読にしない）。既読は詳細の画面のボタンで付ける。
- 見られるのは**管理者だけ**（メンバーは見られない）。問い合わせには個人情報が入りうるため、見られる人を絞る。管理画面のナビに「お問い合わせの管理」を足す（`AdminNavFeature`）。今のナビはロールで絞らないため、管理者だけに出す印を `AdminNavFeature` の口に足す（11節）。
- 本文の段落の表示は、お知らせの `paragraphs` をCoreに移して共通で使う。
- 経路は文字列のリテラルで登録し、`test/admin_ui_test.go` の見本の表（未読・既読・スパム・無記名の4件、失敗の送信）に足す。

## 6. データ

```sql
CREATE TABLE IF NOT EXISTS contact_messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL DEFAULT '',
    reply_to TEXT NOT NULL DEFAULT '',
    body TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'unread' CHECK (status IN ('unread','read','spam')),
    created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_contact_messages_created ON contact_messages(created_at);
```

- `owners` に紐づけない（閲覧者のセッションと無関係に、保持期間まで残す）。
- 入力の検査は `form.Line`（お名前・返信先）と `form.Text`（内容）。制御文字を拒否する。
- 受付の上限の判定と保存は、1つのトランザクションで行う（同時の送信で上限を超えないため）。
- `docs/domain/contact.md` に用語・状態・不変条件を書く。

不変条件の案:
- CONTACT-INV-1: 公開のフォームはCookieを発行・照合せず、IPアドレス・User-Agentを保存しない。応答は `no-store`。
- CONTACT-INV-2: 保持期間を過ぎたお問い合わせは、状態に関係なく `Purge` で削除される。
- CONTACT-INV-3: 受信箱は管理者だけが見られる（メンバー・未ログインは拒否）。
- CONTACT-INV-4: 署名が合わない・期限切れ・使用済みのフォームの値では保存しない。使用済みの記録は保存に成功したときだけ付ける。
- CONTACT-INV-5: 全体の受付上限は保存した件数で数え、超えたら保存しない。
- CONTACT-INV-6: ログに入力の中身（内容・お名前・返信先）を出さない。
- CONTACT-INV-7: 管理画面のGETは状態を変えない。
- CONTACT-INV-8: 人の誤りでありうる判定（署名・期限・使用済み・URLの数・上限）は、黙って捨てず、理由と入力を返す。

## 7. テスト

- 公開のフォーム: Cookieを発行しない、`Cache-Control: no-store`、他のサイトからの送信の拒否、ラベル・`aria-invalid`・入力の保持（`/admin` の外なので、この機能のテストで確かめる）、成功で303と完了の文。
- スパム対策: 各判定で保存しないこと、受け付けたふり・400・503の出し分け、ログの理由の分類。**欄のエラーや期限切れで再表示した直後に再送信しても保存されること**。使い捨ての記録が保存時だけ増えること。鍵を作り直した（再起動の）後の送信が400で入力を残すこと。上限の計数に捨てた送信が入らないこと。時刻はテスト用に差し替えられるようにする。
- 設定: `CONTACT_RETENTION_DAYS` と上限の環境変数の検証（0・範囲外・文字列で起動を止める）、`CONTACT_FORM_URL` との同時設定で起動を止める。
- 管理画面: 管理者だけが見られる（メンバーはナビにも出ない）、GETで状態が変わらない、既読・未読・スパム、1件とスパムのまとめての削除（0件の転送）。`test/admin_ui_test.go` の見本の表に足す。
- 保持期間: 期限を過ぎたものだけが、状態に関係なく `Purge` で消える。
- ログ: 入力のカナリアがログに出ない（既存のカナリアテストの形）。
- Site: お問い合わせが有効なときのLPのボタン（同じタブ・補足文なし）と、プライバシーポリシーの節の出し分け。
- 不変条件の番号をテスト関数のコメントに書く（`test/domain_test.go` の突合）。データ台帳との突合（既存のテスト）。
- わざと崩して落ちることの確認と、見本の画面の撮影（公開のフォーム・受信箱）。

## 10. 守らない範囲・残るリスク

- 人が手で書く宣伝、フォームを開いてから3秒以上待って送る作りのボットは防げない。受信箱のスパムの印と、まとめての削除で後始末する。
- 全体の受付上限は、攻撃されている間、普通の人も送れなくなる（1時間20件を送られると、その1時間は止まる）。前段のレート制限で軽くする。
- `Sec-Fetch-Site` を送らない古いブラウザからは送れない。
- 返信先に書かれた連絡先の真偽は確かめない。
- 通知が無いため、管理画面を見ないまま保持期間を過ぎると、未読のまま消える。一覧に件数と期限を出して補う。
- 秘密鍵と使い捨ての記録はメモリにだけあり、複数のサーバーで動かす構成は考えない（このキットは1台で動かす前提）。

## 12. 外部レビューの反映（2026-10-29、Fable）

| 重要度 | 指摘 | 反映 |
|---|---|---|
| 高 | 欄のエラーの再表示で値を発行し直すと、すぐ再送信した人が「3秒未満」で黙って捨てられる | 400の再表示では、期限内の元の値を埋め直す（4.1） |
| 高 | URLの数と使い回しの「受け付けたふり」は人を巻き込む | URLの数は欄のエラー、使い回しは400。受け付けたふりはハニーポットと3秒未満だけ |
| 高 | データ台帳1節の「一切取得しない」と矛盾する | 1節に但し書きを足す |
| 高 | 使い捨ての記録の上限が無い | 保存に成功したときだけ記録する（上限は受付上限に従う） |
| 中 | 上限に捨てた送信を数えると、ボットが安く人を締め出せる。再起動で計数が消える | 保存した件数だけ、DBで数える |
| 中 | ハニーポットは部品で作れない、自動入力で埋まる名前を避ける | 許可リストの例外、意味の無い名前 |
