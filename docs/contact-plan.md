# お問い合わせ機能 実装計画

状態: 2026-10-29、計画の段階。利用者の依頼「サイトの中にお問い合わせ窓口を持ち、IPアドレスを記録せず、外部のCAPTCHAを使わずにスパムを防ぐ」による。外部レビュー前。承認境界2（保存データの追加）に当たるため、11節の決定と承認を得てから実装する。

## 1. 目的と範囲

サイトの中にお問い合わせのフォーム（`/contact`）を置き、届いた内容を管理画面の受信箱で読めるようにする。今は外部のフォームサービスのURL（`CONTACT_FORM_URL`）へのリンクだけで、問い合わせの内容がその事業者に渡る。自前で持つことで、何を・どこに・いつまで保存するかを運営者が説明できるようにする。

- 新しい同梱機能 `contact`（`features/contact/`、`make add-contact`）。管理者認証（`features/auth`）を使う。お知らせ・カタログとは独立。
- **メールは送らない**。届いたことは管理画面で確かめる（外部通信を増やさない。承認境界3に当たらない）。
- **IPアドレス・User-Agent・Cookieを使わない、記録しない**。公開のフォームはセッションを作らない。
- **外部のCAPTCHA・JavaScriptを使わない**（承認境界3・4に当たらない）。
- 作らないもの: 返信機能（運営者は、本人が書いた返信先へ自分で連絡する）、添付ファイル、問い合わせの種別ごとの振り分け、自動返信、受信の通知。

## 2. 受け取る情報（承認境界2）

| 項目 | 必須 | 上限 | 目的 |
|---|---|---|---|
| お問い合わせ内容 | 必須 | 2,000文字 | 問い合わせへの対応 |
| お名前 | 任意 | 50文字 | 返信のときの呼び方 |
| 返信先（メールアドレス・電話番号など） | 任意 | 200文字 | 返信が必要な場合の連絡先。形式は検査しない（メール・電話・SNS等、本人が選ぶ） |

- 返信が要らない人は、内容だけで送れる。画面で「返信が必要な場合だけ書いてください」と案内する。
- 保存するのは上の3つと、受付日時・状態（未読・既読・スパム）だけ。IPアドレス・User-Agent・送信元のページは保存しない。
- **保持期間**: 受付から90日で自動で削除する（`PurgeFeature`）。管理画面からも個別・まとめて削除できる。期間は環境変数 `CONTACT_RETENTION_DAYS`（1〜365、既定90）で変えられる。バックアップの複製には、その保持期間のあいだ残る（プライバシーポリシーとデータ台帳に書く）。
- プライバシーポリシーには `PrivacyFeature` で表を載せる。今の「お問い合わせでお預かりする情報（外部フォーム）」の節は、`CONTACT_FORM_URL` を使う構成のときだけ出す。

## 3. 公開のフォーム

- `GET /contact`: フォーム。`POST /contact`: 送信。送信に成功したら `/contact?sent=1` へ303で移り、完了の文を出す（再送信を防ぐ）。
- 独立経路（`IsolatedRoutesFeature`）。Cookieを発行せず、セッションを作らない。CSPは `script-src 'none'` のまま。
- 状態を変える `POST` は、`guard.SameOrigin`（`Sec-Fetch-Site: same-origin` と `Origin`）で他のサイトからの送信を拒否する。セッションが無いため、CSRFトークンの代わりに、4節の署名つきのフォームの値を使う。
- 画面は部品（`field`）と、公開ページのレイアウト（Siteのヘッダー・フッター）で作る。入力の誤りは、その欄にエラーを出し、入力を残して400で返す（`docs/components.md` の決まり）。
- 紹介のLP等のお問い合わせのボタンは、この機能が有効なとき `/contact` を指す。Siteは「他の機能があるか」で分岐せず、お問い合わせの行き先を申告する口（例: `ContactLinkFeature`）で受け取る。`CONTACT_FORM_URL` を設定した場合はそちらを優先する（外部フォームを使い続けたい運営者向け）。

## 4. スパム対策

単純なボットをアプリで落とし、連打はCloudflare等の前段で抑え、それでも漏れた分は全体の上限で受信箱を守る。完全には防げない（人が手で書く宣伝は防げない）ことを文書に書く。

### 4.1 アプリの中（IP・外部サービスを使わない）

| 対策 | 仕組み | 判定したとき |
|---|---|---|
| 見えない入力欄（ハニーポット） | 人には見えない入力欄を1つ置く。CSSで画面外に出し、`aria-hidden`・`tabindex="-1"`・`autocomplete="off"`、ラベルは「この欄は空のままにしてください」。値があれば捨てる | 受け付けたふりをする（完了画面へ移す） |
| 署名つきのフォームの値 | `GET /contact` で、発行時刻と使い捨ての乱数を、サーバーの秘密鍵でHMAC-SHA256の署名をした値をフォームに埋め込む。秘密鍵は起動時に `crypto/rand` で作り、メモリにだけ置く（保存しない） | 署名が合わない・形式が違う: 400で「もう一度送信してください」と出し、入力を残す |
| 送信までの時間 | 発行から3秒未満の送信は捨てる。1時間を過ぎた値は期限切れ | 3秒未満: 受け付けたふり。期限切れ: 400で「時間が経ったため、もう一度送信してください」と出し、入力を残す |
| 使い捨て | 使った乱数をメモリに1時間覚え、同じ値の2回目は捨てる（1回取ったフォームの値で連続送信されるのを防ぐ） | 受け付けたふり |
| 中身の規則 | 内容のURL（`http://`・`https://`・`www.`）は2つまで | 受け付けたふり |
| 全体の受付上限 | サイト全体で、1時間に20件・1日に100件まで（環境変数で変更可）。未読が500件を超えたら受け付けない | 「現在、お問い合わせの受付を一時停止しています」と出す（503） |

- 「受け付けたふり」は、ボットに判定の理由を教えないため。人が誤って判定される余地が小さい対策（ハニーポット・3秒・URL数・使い捨て）だけに使う。
- 判定の結果は、理由ごとの固定の分類（`honeypot`・`too_fast`・`expired`・`bad_token`・`replayed`・`too_many_links`・`over_limit`）でログに1行出す。入力の中身は出さない。どの対策が効いているかを、後からログで数えられるようにする。
- 再起動で秘密鍵と使い捨ての記録は消える。開いていたフォームは「もう一度送信してください」になる（入力は残る）。

### 4.2 前段（Cloudflare等）

キットの範囲外として、`docs/deploy.md` に推奨を書く。Cloudflareの無料プランのレート制限のルールは、1つだけ・条件はパスだけ（GETとPOSTを区別できない）・数える時間と止める時間は10秒（2026-10-29に公式の資料で確認）。`/contact` に「同じIPから10秒に5回まで」のようなルールを掛けると、連打を抑えられる。IPで判定するのは前段で、アプリはIPを受け取らない。

### 4.3 使わないもの

- CAPTCHA（Cloudflare Turnstile・reCAPTCHA等）: 外部のスクリプトとJavaScriptが要る（承認境界3・4）。上の対策で防げなくなったときの最後の手段として、文書に書くだけにする。
- JavaScriptでの計算による証明: JavaScriptが要り、本気のボットには効きにくい。
- IPアドレスごとの上限: IPを扱わない方針のため。前段に任せる。

## 5. 管理画面（受信箱）

| 画面 | 型 | 内容 |
|---|---|---|
| `GET /admin/contact` | 一覧 | 受付日時・状態・お名前（無ければ「（無記名）」）・内容の冒頭30文字。新しい順、20件ずつ。未読の件数を見出しの下に出す |
| `GET /admin/contact/{id}` | 詳細 | 全文・お名前・返信先・受付日時・状態。開くと既読にする。操作は「スパムにする」「未読に戻す」、削除のリンク |
| `GET /admin/contact/{id}/delete` | 削除の確認 | 1件の削除 |
| `GET /admin/contact/spam/delete` | 削除の確認 | スパムの印を付けたものを、まとめて削除 |

- 見られるのは**管理者だけ**（メンバーは見られない）。問い合わせには個人情報が入りうるため、見られる人を絞る（11節で決める）。
- 返信先は、リンクにせず文字で表示する（`mailto:` 等の自動のリンクを作らない。誤った宛先への送信や、書かれたURLを開く危険を避ける）。
- 管理画面のナビに「お問い合わせ」を足す（`NavLinkFeature`）。未読の件数は一覧の画面にだけ出す。

## 6. データ

```sql
CREATE TABLE IF NOT EXISTS contact_messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL DEFAULT '',
    reply_to TEXT NOT NULL DEFAULT '',
    body TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'unread' CHECK (status IN ('unread','read','spam')),
    created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_contact_messages_created ON contact_messages(created_at);
```

- `owners` に紐づけない（閲覧者のセッションと無関係に、保持期間まで残す）。
- 入力の検査は `form.Line`（お名前・返信先）と `form.Text`（内容）。制御文字を拒否する。
- `docs/data-inventory.md` に1節、`docs/domain/contact.md` に用語・状態・不変条件（`CONTACT-INV-*`）を書く。

不変条件の案:
- CONTACT-INV-1: 公開のフォームはCookieを発行・照合せず、IPアドレス・User-Agentを保存しない。
- CONTACT-INV-2: 保持期間を過ぎたお問い合わせは、`Purge` で削除される。
- CONTACT-INV-3: 受信箱は管理者だけが見られる（メンバー・未ログインは拒否）。
- CONTACT-INV-4: 署名が合わない・期限切れ・使用済みのフォームの値では保存しない。
- CONTACT-INV-5: 全体の受付上限を超えたら保存しない。
- CONTACT-INV-6: ログに入力の中身（内容・お名前・返信先）を出さない。

## 7. テスト

- 公開のフォーム: Cookieを発行しない、他のサイトからの送信の拒否、入力の誤り（欄のエラー・入力の保持）、成功で303と完了の文。
- スパム対策: 各判定（ハニーポット・3秒未満・期限切れ・署名の改ざん・使い回し・URLの数・全体の上限・未読の上限）で保存しないこと、受け付けたふりと400・503の出し分け、ログの理由の分類。時刻はテスト用に差し替えられるようにする。
- 管理画面: 管理者だけが見られる、既読・スパム・未読に戻す、1件とスパムのまとめての削除。`test/admin_ui_test.go` の見本の表に足す。
- 保持期間: 期限を過ぎたものだけが `Purge` で消える。
- ログ: 入力のカナリアがログに出ない（既存のカナリアテストの形）。
- `docs/data-inventory.md`・`docs/domain/contact.md` との突合（既存のテスト）。

## 10. 守らない範囲・残るリスク

- 人が手で書く宣伝、フォームを開いてから3秒以上待って送る作りのボットは防げない。受信箱のスパムの印と、まとめての削除で後始末する。
- 全体の受付上限は、攻撃されている間、普通の人も送れなくなる。前段のレート制限で軽くする。
- 返信先に書かれた連絡先の真偽は確かめない。
- 秘密鍵と使い捨ての記録はメモリにだけあり、複数のサーバーで動かす構成は考えない（このキットは1台で動かす前提）。

| 2 | 保持期間 | 既定90日。環境変数で1〜365日 |
| 3 | 受信箱を見られる人 | 管理者だけ |
