# 固定ページ機能 実装計画

状態: 2026-10-30、計画の段階。利用者の依頼「会社概要・採用情報などのページを管理画面で作れるようにする」による。本文の書き方は、利用者が「書き方を絞ったMarkdownを、キットのコードで解釈する」（案A）に決めた。外部レビュー前。承認境界2（DBの表の追加）に当たるため、10節の決定と承認を得てから実装する。

## 1. 目的と範囲

管理画面で、`/about` のような1階層のURLのページを作り、下書き・公開できるようにする。本文には見出し・箇条書き・リンク・表を書ける。

- 新しい同梱機能 `pages`（`features/pages/`、`make add-pages`・`remove-pages`）。管理者認証を使う（有効な間は `remove-auth` を拒否する）。
- 本文の書き方（3節）はCoreの部品にし、後からお知らせ等でも使えるようにする（今回はお知らせの本文は変えない）。
- 個人情報を載せる場所ではない（公開する文章）。閲覧者の情報は取得しない。
- 作らないもの: 画像・ファイルの添付、HTMLの直接入力、階層のあるURL（`/company/about`）、版の履歴、予約公開、ページごとのレイアウトの選択、JavaScriptでのプレビュー。

## 2. 画面と経路

| 経路 | 内容 |
|---|---|
| `GET /{slug}` | 公開中のページ。下書き・存在しないページは404（Siteがあれば、Siteの404の画面） |
| `GET /admin/pages` | 一覧（タイトル・URL・状態・ナビの順・更新日時） |
| `GET /admin/pages/new`、`POST /admin/pages` | 作成 |
| `GET /admin/pages/{id}`、`POST /admin/pages/{id}` | 編集。「プレビュー」ボタンで、保存せずに描いた本文をフォームの上に出す（POST、JSなし） |
| `POST /admin/pages/{id}/publish`・`unpublish` | 公開・下書きに戻す |
| `GET /admin/pages/{id}/delete`、`POST /admin/pages/{id}/delete` | 削除の確認と削除 |

- 管理画面は `docs/components.md` の画面の型（一覧・作成・編集・削除の確認）で作り、`test/admin_ui_test.go` の見本の表に足す。
- 編集できるのは管理者とメンバー（カタログと同じ）。
- **URL（スラッグ）**: 英小文字・数字・ハイフン、2〜40文字、ハイフンで始まり・終わらない。**予約語**（他の機能・Coreが使う最初の区切り: `admin`・`api`・`news`・`catalog`・`contact`・`privacy`・`static`・`account`・`favicon.ico`・`robots.txt`・`sitemap.xml` 等）は使えない。予約語は固定の一覧に加え、起動時に登録された経路の最初の区切りから集めて足す（新しい機能を足しても衝突しない）。
- `GET /{slug}` はServeMuxで1階層だけに当たり、より具体的な経路（`/news`・`/contact` 等）が優先される。ページが無いときの404は、Siteの404の画面を描く口（`NotFoundFeature` を受け取る）で返す。
- 公開ページはCookieを発行・照合しない。公開・非公開の反映を遅らせないため、公開キャッシュは使わない（カタログと同じ）。

## 3. 本文の書き方（Coreの部品 `richtext`）

書き方を絞ったMarkdownを、キットのコードで**構造（ブロックと文字の並び）に読み**、`html/template` の部品で描く。HTMLの文字列を組み立てず、`template.HTML` も使わない（エスケープを回避する経路を作らない）。

| 要素 | 書き方 | 出力 |
|---|---|---|
| 見出し | 行頭の `## `・`### ` | `h2`・`h3`（`h1` はページのタイトル。`#` 1つは書けない） |
| 段落 | 空行で区切る。段落の中の改行はそのまま改行 | `p`（改行は `br`） |
| 箇条書き | 行頭の `- ` | `ul`（`class` 付き） |
| 番号付き | 行頭の `1. ` 等の数字とピリオド | `ol` |
| 表 | `\| 見出し \| 見出し \|` の次の行に `\|---\|---\|`、続けて行 | `table`（1行目は `th scope="col"`）。`caption` はページのタイトルと表の位置から付ける（例:「表1」） |
| リンク | `[文字](URL)` | `a`。URLは `https://` か、`/` で始まるサイト内のパス（`//` で始まるものは不可）だけ。それ以外は文字のまま出す。外部のリンクは `rel="noopener noreferrer"` |
| 強調 | `**文字**` | `strong` |

- 入れ子（リストの中のリスト）、引用、コード、画像、HTMLの直接入力は扱わない。書けない記号は文字としてそのまま出す。`\` で次の記号を文字にできる。
- 上限: 本文5万文字、表は20列・200行まで。超えたら欄のエラー。
- 読む処理は、決まった入力から決まった構造を返す純粋な関数にし、表で網羅的にテストする（各要素、組み合わせ、書けない記号、危ないURL、エスケープ）。Goのファズテスト（`testing.F`）で、どんな入力でも止まらず、描いた結果に `<script` 等が文字以外として出ないことを確かめる。
- 管理画面に、書き方の早見表を `<details>` で出す。

## 4. ナビゲーションとsitemap

- ページごとに「ナビに出す順」（空ならナビに出さない）を持つ。公開中で順のあるページだけを、Siteのヘッダーのナビに載せる。
- 今のナビの口（`NavLinkFeature`）は起動時に1回だけ読むため、公開・順の変更が反映されない。描画のたびにリンクを返せる口に広げる（例: `NavLinks()` を起動時の値と、描画時に呼ぶ関数の2通りにする）。どの形にするかはレビューで決める。
- 公開中のページは sitemap.xml に載せる（既存の `SitemapFeature`）。

## 5. データ（承認境界2）

```sql
CREATE TABLE IF NOT EXISTS pages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    slug TEXT NOT NULL UNIQUE,
    title TEXT NOT NULL,
    body TEXT NOT NULL DEFAULT '',
    status TEXT NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'published')),
    nav_order INTEGER,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
```

- 公開する文章で、個人情報は入れない運用（画面で案内する）。作者のアカウントは保存しない。明示削除まで保持する。`owners` に紐づけない。
- `docs/data-inventory.md` に節を足し、`docs/domain/pages.md` に用語・状態・不変条件（`PAGES-INV-*`）を書く。

不変条件の案:
- PAGES-INV-1: 公開ページに出るのは公開中のページだけ。下書き・存在しないページは同じ404。
- PAGES-INV-2: 本文は構造に読んでから部品で描き、利用者の入力をHTMLとして出さない。リンクは `https://` とサイト内のパスだけ。
- PAGES-INV-3: スラッグは決まった形で、予約語（他の機能の経路を含む）と重ならず、重複しない。
- PAGES-INV-4: 管理操作は管理者認証の Page・Form で守り、変更はPOSTだけ。
- PAGES-INV-5: 公開ページはCookieを発行・照合しない。
- PAGES-INV-6: ナビとsitemapに出るのは公開中のページだけ。

## 6. テスト

- 本文の部品: 3節の表どおりの網羅、ファズテスト、危ないURL（`javascript:`・`data:`・`//`・大文字小文字の混在・空白・制御文字）。
- 経路: 公開・下書き・存在しないページの応答、Cookie無し、予約語・他の機能の経路と同じスラッグの拒否、`/news` 等が優先されること。
- 管理画面: 作成・編集・プレビュー（保存しない）・公開・削除、入力の誤り（欄のエラー・入力の保持）、`test/admin_ui_test.go` の見本と失敗の見本。
- ナビ・sitemap: 公開・順の変更が、再起動なしで反映されること。
- 不変条件の番号とテスト、データ台帳の突合（既存のテスト）。わざと崩して落ちることの確認、見本の画面の撮影。

## 7. 文書

README、`docs/components.md`（本文の部品と書き方）、`docs/data-inventory.md`、`docs/domain/pages.md`、スキル（範囲の1行）、LPの同梱機能の説明。

## 8. 進め方

1. 外部レビュー（Fable）と、10節の決定・承認境界2の承認。
2. 本文の部品（読む処理とテスト・ファズテスト）を先に作り、部品だけでもう一度レビューを受ける（自前で解釈する部分のため。認証の検証部分と同じ扱い）。
3. 機能（ストア・公開ページ・管理画面）、ナビの口の拡張、`cmd/kit`。
4. テスト、わざと崩す確認、撮影、文書。
5. 紹介サイトで有効にして、VPSに置く。

## 9. 守らない範囲・残るリスク

- Markdownの方言との完全な互換は目指さない。書ける要素は3節の表だけで、他は文字として出す。
- 外部のリンク先の内容と安全は確かめない。
- 版の履歴が無いため、上書きした本文は戻せない（バックアップから戻す）。

## 10. 決めること

| # | 事項 | 提案 |
|---|---|---|
| 1 | URLの形 | `/{slug}`（1階層）。予約語と他の機能の経路は使えない |
| 2 | 書ける要素 | 3節の表（見出し2段、段落、箇条書き、番号付き、表、リンク、強調） |
| 3 | 編集できる人 | 管理者とメンバー |
| 4 | ナビ | ページごとの「ナビに出す順」。公開中のものだけ載せる |
| 5 | 公開キャッシュ | 使わない（反映を遅らせない） |
| 6 | プレビュー | 編集画面のボタン（保存しない） |
