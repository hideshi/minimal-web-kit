# ドメインモデル草案: カタログ

未実装の設計案。現在の仕様の正本ではない。実装時に `docs/domain/catalog.md` へ移し、以下の番号をテストと対応づける。計画は [catalog-plan.md](catalog-plan.md)。

## 用語と関係

- 項目（Item）: 商品・サービス・事例等の1件。タイトル・本文と公開状態を持つ。
- カテゴリ（Category）: 項目の単一分類。未分類も許す。
- タグ（Tag）: 項目の複数分類。1項目20個まで。
- 公開: 誰でも閲覧できる状態。予約公開は初版では扱わない。

カテゴリ 0..1 ← 多数の項目。項目とタグは関連表による多対多。
項目はサイト全体の共有内容で、匿名OwnerIDや認証アカウントの所有物ではない。認証アカウントは操作を許可するためだけに参照する。

## 状態

作成 → 下書き ⇄ 公開 → 削除。下書きからも削除できる。
カテゴリ削除 → 関連項目を未分類にする。分類変更・関連変更は項目のupdated_atにも反映する。タグ削除 → 関連だけ削除する。どちらも項目自体は削除しない。
作成・編集だけでは公開しない。削除は確認画面を経る。

## 不変条件案

| 番号 | 条件 | 実装・検証予定 |
|---|---|---|
| CATALOG-INV-1 | 公開ページ・検索件数・分類候補・sitemapに出るのは公開項目とその関連だけ。未公開詳細は404。公開候補にない分類IDは、存在しないIDと同じ200の空一覧・同じ文言にする | 公開専用SQLとHTTP検証 |
| CATALOG-INV-2 | タイトル・本文・分類名はプレーンテキストとしてエスケープする | テンプレート検証 |
| CATALOG-INV-3 | 管理操作は管理者認証のPage/Formで保護し、変更はPOSTのみ | 全管理経路の認証・CSRF検証 |
| CATALOG-INV-4 | 項目とタグ関連は同一トランザクションで保存し、失敗時は部分保存しない | SQLiteロールバック検証 |
| CATALOG-INV-5 | 分類削除は項目を消さず、項目削除はその関連だけを消す。孤立した関連行を残さない | FK・削除検証 |
| CATALOG-INV-6 | 項目・カテゴリ・タグのIDを再利用せず、同種の正規化済み分類名は重複させない | AUTOINCREMENT・UNIQUE検証 |
| CATALOG-INV-7 | 公開閲覧で匿名セッションを照合・発行・消去せず、Cookieを追加しない | 独立経路とCookie検証 |
| CATALOG-INV-8 | 内容はCoreのGC・アカウント削除・機能無効化では削除しない | 保存範囲と再初期化検証 |
| CATALOG-INV-9 | 内容・検索語・入力値をログやエラー文言に含めない | カナリア検証 |
| CATALOG-INV-10 | 一覧の通常HTMLと断片で公開判定と検索条件を共有し、JSなしでも全ての重要操作が可能 | 通常/断片/履歴/フォーム検証 |

| CATALOG-INV-11 | タイトル1〜200字・本文50,000字以下・分類名1〜50字・1項目20タグ以下。タイトルと分類名は正規化し改行・制御文字を拒否。管理側の存在しない分類IDは保存しない | 正規化・保存検証 |
| CATALOG-INV-12 | 検索語200字・タグ条件20個・page上限5,000。検索の構文不正は400とし、分類の存在有無で応答を変えない | GET入力検証 |

## 権限

| 操作 | 管理者 | メンバー | 未ログイン |
|---|---|---|---|
| 公開項目の閲覧 | 可 | 可 | 可 |
| 項目・カテゴリ・タグの管理 | 可 | 可 | 不可 |

業務上の承認フローや項目単位の権限は設けない。Authのアカウント管理権限は変更しない。

## 境界

Newsとはデータ・公開条件を共有しない。共通化するのは既存の認証・レイアウト等の口まで。画像・予約公開・注文・API・静的書き出し・作者記録は初版の範囲外。
検索条件は共有可能なURLに含まれ、ブラウザ履歴等には残り得る。アプリで検索履歴は保存しない。
