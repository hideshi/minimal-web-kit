# 取得・保存データ台帳 (data-inventory.md)

この文書は、本アプリケーションの取得・保存データについて、利用目的・保存先・保持期間・削除方法を管理する正本（SoT）です。氏名などを既定で取得しない方針と、現在のひな形の保存項目を記録します。

## テーブル定義書との役割分担
- 本台帳は、何の情報を、何のために、どこへ、いつまで保存し、どう削除するかを管理します。
- テーブル定義書を別途作成する場合、型・制約・関連などDB構造の詳細はそちらで管理し、本台帳と相互参照します。利用目的・保持・削除の方針を別の正本へ重複させません。
- 現状は独立したテーブル定義書がないため、本台帳にDB照合用のテーブル・列一覧と型等の補助情報を併記しています。実DBの構造はマイグレーションSQLで実装します。
- `test/data_schema_test.go` は本台帳と実スキーマのテーブル名・列名を双方向に照合します。型・NULL制約・外部キーの一致や、本台帳に書かれた保持・削除方針すべてを保証する検査ではありません。

列や保存項目を追加する場合は、事前に利用者の承認を得て本台帳を更新してください。外部フォーム・Cookie・ログ等の扱いを変更する場合も、対象の情報・保存先・目的・保持・削除方法を本台帳で明確にし、画面の説明と揃えます。
本台帳はmakeコマンドで自動生成・更新されません。テストは読み取りだけを行います。

## 1. 取得・保存しない情報（明示的な非取得）

以下の情報は、本システムでは**一切取得・保存しません**（お問い合わせ機能を有効にした場合、送る人が任意で書くお名前・返信先と、運営者が対応のために書くメモを除く。§7を参照）。
- 氏名、ニックネーム（管理者認証のアカウントの「呼び名」は、アカウントを見分けるための運用上のラベルで、実名・メールアドレスを入れない運用とする。§4を参照）
- メールアドレス、電話番号、住所
- 生年月日、年齢、性別
- パスワード（実名不要なセッションのみで識別）
- 接続元IPアドレス、User-Agent（アクセスログにも記録しない）
- 指紋・顔などの生体情報（管理者認証のパスキーでは、生体認証は認証器の中で完結し、サーバーには届かない）

## 3. データの破棄とライフサイクル

1. **ユーザー自身による即時削除**:
   - セッション破棄操作（`/account/delete-all`）により、当該 `owner_id` を `owners` テーブルから削除。外部キーの `ON DELETE CASCADE` により、稼働データベース上の紐づく全セッションおよび各機能のレコードが自動的に連動削除されます。
2. **放置セッションの自動GC（Garbage Collection）**:
   - サーバー起動時および1時間ごとの処理により、最終アクセスから30日以上経過したセッションを削除します。
   - 有効なセッションが1件も残っていない所有者を `owners` テーブルから削除し、カスケードにより紐づくデータを一括削除します。同じ所有者に有効なセッションが残っている場合は、所有者とデータを残します。
   - このため、`owners` へCASCADEで紐づけるのは、ブラウザ単位の一時データに限ります。お知らせの記事や業務データのように残すべきデータは `owners` に紐づけず、保持期間と削除方法を本台帳に別途定めます。
3. **ブラウザ側でのCookie消去**:
   - ブラウザ側でCookieを削除した場合は、端末からのセッション識別が切断されます。サーバー上の残存レコードは最終アクセスから30日経過後に自動GCされます。
4. **DBの複製**:
   - `backup` コマンドの複製と、表を作り直す移行の前の複製（`pre-migration-*.db`）は、DB全体を含みます。権限は所有者だけが読める0600です。
   - 自動では消えません。保持期間と保存先は運営者が決め、プライバシーポリシーに書いて、期限を過ぎたものを削除します（[deploy.md](deploy.md) の8節・9節）。稼働DBで削除したデータも、削除前の複製には残ります。

## 4. 管理者認証（パスキー）のデータ（`make add-auth`・`make add-news` で有効化した場合のみ）

管理者認証（`features/auth`）を有効化すると、起動時に `features/auth/migration.sql` で以下のテーブルを作成します（既存のデータは削除しません）。お知らせ機能を有効化すると、管理者認証も一緒に有効になります。登録を無効化してもテーブルとデータは残ります。

この節の要約は、管理者認証の `PrivacyNotices`（`features/auth/auth.go`）でプライバシーポリシーの画面に載ります。保存項目・保持期間を変えたら、両方を揃えてください。

アカウント・パスキー・管理者セッションは匿名の所有者（`owners`）に紐づけません。Coreのセッション破棄や30日放置のGCでは削除されません。氏名・メールアドレス・パスワード・生体情報は保存しません。

アカウント導入前の形式（`auth_settings` がある）のDBでは起動を止めます。`auth-recover -reset-schema` で管理者認証の表だけを作り直します（パスキーは登録し直し。他の機能のデータは残ります）。

### テーブル: `auth_accounts`
管理画面にログインできるアカウント。ロールはシステム管理者（`admin`）とサイト管理者（`member`）。

| 列名 | 型 | NULL許可 | 保存目的 | 保持期間 | 備考 |
|---|---|---|---|---|---|
| `id` | INTEGER | NO | アカウントの識別 | システム管理者が削除するまで | 連番。ログにはこの番号だけを記録する |
| `name` | TEXT | NO | 管理画面でアカウントを見分ける呼び名 | 同上 | 50字以内・重複不可。運用上のラベルで、実名・メールアドレスを入れないよう画面で案内する。認証器のアカウント選択（displayName）にも表示される。ログに記録しない |
| `role` | TEXT | NO | 権限の判定 | 同上 | `admin`（アカウントの管理もできる）・`member`（各機能の管理画面）・`user`（公開サイトの編集はできない）。`user` は共通認証で外部にログインする構成（`federated_accounts`）には無い |
| `webauthn_user_id` | BLOB | NO | 認証器に登録するアカウントの識別子 | 同上。鍵のリセット・`auth-recover` で再生成 | ランダム16バイト。個人名を含まない |
| `created_at` | INTEGER | NO | 作成日時の表示 | 同上 | UNIXエポック秒 |
| `disabled_at` | INTEGER | YES | 停止の記録 | 同上 | UNIXエポック秒。停止中はログインできない |
| `last_login_at` | INTEGER | YES | 最終ログイン日時の表示 | 同上 | UNIXエポック秒 |

| 列名 | 型 | NULL許可 | 保存目的 | 保持期間 | 備考 |

| `id` | BLOB | NO | 認証器の識別（credential ID） | 本人かシステム管理者が削除するまで。アカウントの削除・鍵のリセット・`auth-recover` で削除 | ログに記録しない |

| `public_key` | BLOB | NO | 署名の検証 | 同上 | 公開鍵（SPKI DER）。秘密鍵は認証器の外に出ない |

| `sign_count` | INTEGER | NO | 複製の疑いの検出 | 同上 | 署名カウンタ。同期型では0のままのことが多く、検出は働かない |
| `label` | TEXT | NO | 管理画面での表示 | 同上 | 端末名、50字以内。個人名を入れないよう案内する |
| `disabled_at` | INTEGER | YES | 複製の疑いによる無効化の記録 | 同上 | UNIXエポック秒 |
| `created_at` | INTEGER | NO | 登録日時の表示 | 同上 | UNIXエポック秒 |

| `expires_at` | INTEGER | NO | 期限の判定 | 同上 | UNIXエポック秒 |

### Cookie: `admin_session`
- 管理者セッションの生トークン。`Path=/admin`、HttpOnly、`SameSite=Strict`、`AUTH_ORIGIN` がhttpsならSecure。
- 公開ページ（`/`、`/news`、`/api/news` 等）には送られず、照合もしません。

### Cookie: `oidc_flow`
- 共通認証の提供機能を登録した場合だけ、認可要求とブラウザを結びつけるために使います。生のトークンはCookieにだけ置き、DBにはSHA-256ハッシュを保存します。`Path=/admin`、HttpOnly、Secure、`SameSite=Strict`。5分で失効し、完了・中止で削除します。

### Cookie: `agent_flow`
- AIエージェントの接続を有効にした場合だけ、認可要求とブラウザを結びつけるために使います。生のトークンはCookieにだけ置き、DBにはSHA-256ハッシュを保存します。`Path=/admin`、HttpOnly、`SameSite=Strict`、`AUTH_ORIGIN` がhttpsならSecure。5分で失効し、完了・中止で削除します。

### DBの外のファイル（共通認証の提供機能）
- 署名秘密鍵（`OIDC_SIGNING_KEY_FILE`）とSDKの暗号化鍵（`OIDC_CRYPTO_KEY_FILE`）。所有者だけが読める権限でなければ起動しません。バックアップを含めて保護し、公開リポジトリに置かないでください。

### 管理者認証のデータの削除
- アカウント: システム管理者が管理画面から削除できます（自分自身と、有効なシステム管理者が0人になる場合を除く）。そのアカウントのパスキー・管理者セッション・登録トークンも削除します。
- パスキー: 本人がパスキーの管理から、システム管理者がアカウントの詳細から削除できます（最後の有効な1件を除く）。`make auth-recover` で全件と全管理者セッションを削除します（`-only <ID>` ならそのアカウントの分だけ）。アカウントと、他の機能のデータ（お知らせの記事等）は残ります。
- 管理者セッション・登録トークン: 期限切れ分をサーバー起動時と1時間ごとのGCで削除します。
- AIエージェントの接続: 期限切れの要求とトークンをGCで削除します。
- 共通認証: 期限切れの要求・秘密値と、保持期間を過ぎた墓標をGCで削除します。`auth-recover -reset-schema` は連携の表も削除します（連携先を登録し直す）。バックアップから戻したときは、公開の前に `oidc-revoke-all -yes` で全連携先のログインを失効させてください。
- テーブルごと削除する場合は、サーバー停止後にDBのバックアップを取ったうえで、利用者自身が実施します。WAL・バックアップに残った過去のデータは、この削除の対象外です。

## 7. お問い合わせ機能のデータ（`make add-contact` で有効化した場合のみ）

`features/contact/migration.sql` の1表。公開のフォーム（`/contact`）から送られた内容を、システム管理者が受信箱で読むために保存します。返信が必要な人だけが、お名前と返信先を任意で書きます。IPアドレス・User-Agent・Cookie・送信元のページは取得・保存しません。メールは送りません。

### テーブル: `contact_messages`

| 列名 | 型 | NULL許可 | 保存目的 | 保持期間 | 備考 |
|---|---|---|---|---|---|
| `id` | INTEGER | NO | お問い合わせの識別 | 下の「お問い合わせのデータの削除」の時期か、システム管理者が削除するまで | AUTOINCREMENT |
| `name` | TEXT | NO | 返信のときの呼び方 | 同上 | 任意（空文字）。50字以内、改行・制御文字不可 |
| `reply_to` | TEXT | NO | 返信が必要な場合の連絡先 | 同上 | 任意（空文字）。200字以内。形式は検査しない（メール・電話等を本人が選ぶ） |
| `body` | TEXT | NO | お問い合わせへの対応 | 同上 | 必須。2,000字以内、URLは2つまで |

| `last_activity_at` | INTEGER | NO | 対応中の削除の時期の計算 | 同上 | UNIX秒。受付のときは `created_at` と同じ。対応中のもののメモの保存と、対応中への変更で進む |

### お問い合わせのデータの削除

- 未読・完了・スパムは、受付から `CONTACT_RETENTION_DAYS`（既定90日）を過ぎたら、起動時と1時間ごとの `Purge` で削除します。
- 対応中は、最後の更新から `CONTACT_RETENTION_DAYS` を過ぎたら削除します。受付から `CONTACT_ACTIVE_MAX_DAYS`（既定365日）を超えて残しません。
- システム管理者は受信箱で1件ずつ、またはスパムの印を付けたものをまとめて削除できます。メモも一緒に消えます。
- 削除は稼働DBの物理削除まで。削除前のバックアップの複製には、その複製の保持期間のあいだ残ります。プライバシーポリシーには、保持期間とバックアップの保持期間を合わせて書いてください。
- スパム対策のフォームの値（署名の鍵・使用済みの記録）はメモリにだけあり、保存しません。判定の結果は固定の分類だけをログに出し、入力の中身は出しません。
