# LPスキル (minimal-web-kit-lp)

このスキルは、固定ページの機能で、1つの製品を相手と切り口ごとに説明するページ（LP）を作るための手順です。書き方の正本は `docs/richtext.md`（2.2節がLPの部品）、固定ページの仕様は `docs/domain/pages.md` です。検索とSNSの共有は `minimal-web-kit-seo` を併用します。データの決まりは `minimal-web-kit-design`、文面の約束の決まりは同じスキルの5節に従い、ここには写しません。

## 1. 先に決めること
1ページに1つの切り口だけを書きます。決まっていなければ推測で埋めず、利用者に聞きます。

| 事項 | 決めること |
|---|---|
| 相手 | 誰に向けたページか（例: WordPressの保守に困っている会社の担当者） |
| 困りごと | 相手が今困っていること。3〜5個 |
| 言葉 | 相手が検索や会話で使う言葉（例: 「WordPress 乗り換え」「脆弱性 対応」）。製品の中の言葉ではなく、相手の言葉 |
| 行動 | 読んだ後にしてほしいこと（例: お問い合わせ、機能の一覧を見る）。1〜2個 |
| 元の資料 | 営業資料、社内の文書、README 等。資料に無い主張は足さない |
| URL | スラッグ（英小文字・数字・ハイフン、2〜40文字）。相手の言葉を英語で短く（例: `lp-wordpress`） |

## 2. 書く順と形
固定ページの本文で書きます。見た目は `style.css` の部品で決まり、HTML・CSS・JSは書けません。

1. **題名**: 相手の言葉を入れて、何が変わるかを1文で。`<title>`・OGPの題名・自動の画像に使われます。32文字くらいまでが、検索結果とSNSで切れにくい目安です（確かな上限ではない）。
2. **最初の画面**: 本文の1行目を `ヒーロー: 導入の文` にし、直後に `ボタン: [文字](/contact)` を1〜2行。導入は `description`（検索結果とSNSの説明文。120文字まで）にもなるので、相手・困りごと・解決を2文以内で書きます。
3. **困りごと**: `## ` の見出しと箇条書き（`- **短い名前**: 説明`）。
4. **変わること**: `## ` の見出しの下に `カード: 題名 | 説明` を3枚か6枚（3列になる）。2枚・4枚は2列。
5. **根拠と比較**: 表（`表: 説明` の行と `|` の表）、番号付きの手順。数字には出典と時点を書きます。
6. **合わない場合**: 向かない相手を正直に書きます（例: 「WordPress のままがよい場合」）。
7. **締め**: もう一度 `ボタン: ` の行。

- 見出しは `## ` と `### ` だけ。カードの題名は、前に `## ` があれば小見出しになります。
- 行頭が `ヒーロー: `・`ボタン: `・`カード: `・`表: ` で始まる普通の文は、`ボタン\:` のように逃がします。
- 書いたら管理画面のプレビューで、最初の画面・カードの並び・狭い画面での見え方を確かめます。

## 3. 検索とSNSのために
サイト全体の決まり（キットが自動でやること、言葉、正確さ、ページのつながり、Search Console）は `minimal-web-kit-seo` に従います。LPに固有の点だけをここに書きます。
- **入口**: 新しいLPは、ナビに出すページ（例: 同梱機能）かトップから必ずリンクし、関係するカタログの項目からもリンクします。
- **重なり**: 同じ製品のLP同士で、題名・導入・見出しを使い回しません。
- **OGPの画像**: 何もしなければ、題名から自動で作られます（1200×630）。写真を使うなら、横長の画像を本文の最初の画像にします（ヒーローの後でよい）。フォントは JIS X 0208 と Windows の文字の範囲（CP932）の文字を持ちます。題名に絵文字や `𠮷` 等の範囲の外の文字があると、サイト共通の画像になります。

## 4. AIで作るとき
- 元の資料を読み、1節の表を埋めてから書きます。表を利用者に見せて、相手と言葉が合っているかを確かめます。
- MCPの `pages_create` で**下書き**を作ります。公開は、利用者が管理画面で確かめてから行います（AIが無断で公開しない）。
- 資料に無い数字・実績・お客様の声を作りません。比較の相手（他社の製品）について、公式の資料で確かめていないことを書きません。
- 本文を書き換えるときは、`pages_get` で今の本文を読み、変える所だけを変えます（`pages_update` は全部の欄を置き換える）。

## 5. 公開の後に確かめること
外から確かめられることは、AIが確かめます。

| 項目 | 確かめ方 |
|---|---|
| 公開 | ページが200で、`<title>`・`description`・`canonical`・`og:image` が意図どおり |
| 画像 | `og:image` のURLが200で `image/png`（自動の画像の時） |
| 見つけられるか | `sitemap.xml` に載り、ナビかトップからリンクがある |
| SNS | Xのカードの表示（投稿の前に確かめる道具があれば使う） |
| 検索 | Search Console にサイトマップを送り、数日後にインデックスと検索の語を見る（運営者が操作する） |
| 効果 | アクセス解析を有効にしたサイトでは、ページごとの閲覧の数（同意した人の分だけ）。問い合わせがどのLPから来たかは、キットでは分からない |

## 6. 約束しないこと
- 検索の順位、問い合わせの増加、表示の回数。
- 未検証の数字、「完全」「必ず」等の言い切り（`minimal-web-kit-design` の5節）。
- SNSがOGPの画像をどう切り抜くか、いつ取り直すか。
