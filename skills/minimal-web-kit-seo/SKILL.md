# SEOスキル (minimal-web-kit-seo)

このスキルは、サイト全体の題名・書き出し・ページのつながりを、検索する人とSNSで共有された時に伝わる形に整えるための手順です。LPの切り口の決め方と書く順は `minimal-web-kit-lp`、文面の約束の決まりは `minimal-web-kit-design` の5節に従い、ここには写しません。

## 1. キットが自動でやること
書き手が触れない所です。まず、ここを前提にします。`SITE_URL` が無い構成では、`canonical`・OGP・`sitemap.xml` は出ません。

| 項目 | 中身 |
|---|---|
| `<title>` | 「ページの題名 - サイト名」。サイト名は Site のレイアウト（`features/site/views/layout.html`）に書く |
| 説明文（`description`・`og:description`） | お知らせの記事とカタログの項目は、本文の書き出し（リンクの記法は文字にし、120文字で切る。本文が空なら題名）。固定ページは、ヒーローの導入か最初の段落。一覧（`/news`・`/catalog`）とトップは決まった文 |
| `canonical` | 各ページ自身。絞り込み（`/catalog?tag=…`・`/news?category=…`）は一覧の本体を指す |
| `sitemap.xml` | 公開中のお知らせ・カタログ・固定ページと、一覧とトップ。固定ページはナビに出さなくても載る |
| `robots.txt` | 全部を許し、サイトマップの場所を書く。検索に載せない指定（`noindex`）は404の画面だけ |
| OGPの画像 | 固定ページは、本文の最初の画像か、題名から自動で作る画像。お知らせとカタログは、サイト共通の画像 |
| 速さ | 公開ページはJS無し（カタログの一覧とアクセス解析を除く）で軽い |

説明文を書く欄は無いので、**本文の書き出しの1〜2文が、そのまま検索結果とカードの説明文になります。**

## 2. 先に決めること
決まっていなければ推測で埋めず、利用者に聞きます。

| 事項 | 決めること |
|---|---|
| 読み手 | 誰が検索して来るか（例: WordPressの保守に困っている会社の担当者、社内の発信を任された人） |
| 言葉 | 読み手が検索に使う言葉。製品の中の言葉（例: WXR、GA4、CSRF）ではなく、読み手の言葉（例: WordPressの書き出し、Googleアナリティクス） |
| 入口 | 読み手を最終的に案内したいページ（お問い合わせ、LP 等） |

## 3. ページの種類ごとの書き方

### お知らせ
- **題名**: 何ができるようになったか、読み手の得を先に。機能名の列挙は短く。30文字くらいまでが、検索結果で切れにくい目安（確かな上限ではない）。
- **書き出し**: 製品名から始めない（サイトの中では分かりきっているので、120文字の枠を使ってしまう）。1文目で「何ができるようになったか」、2文目で「誰に効くか」。
- 詳しい機能の説明は、カタログの項目へリンクして任せます。

### カタログ
- **題名**: 「機能名 — 一言」の形を揃えます。
- **書き出し**: 「〇〇する機能です」より先に、「誰の、どんな困りごとが減るか」を書きます。専門用語は2文目以降に。
- 既定の値や設定で変わる動き（保持の日数、受け付ける認証器の種類 等）は、「既定では」を付けて、README と `docs/domain/` の今の記述に合わせます。設定を変えないと使えないことを、既定の動きのように書きません。

### 固定ページ・LP
- 書き方は `minimal-web-kit-lp`。題名とヒーローの導入（説明文になる）は、このスキルの2節の言葉で書きます。

## 4. 正確さ
検索とSNSの説明文は、本文の書き出しが文脈なしで切り出されます。書き出しは特に、次を確かめてから公開します。
- 機能の説明が、今の README・`docs/domain/`・設定の既定値と合っているか。数（スキルの本数、依存の数、日数 等）は、変わるたびに古くなりやすいので、書くなら確かめた日を添えるか、書かずに済ませます。
- 「完全」「必ず」「心配がありません」等の言い切りを避けます（`minimal-web-kit-design` の5節）。
- 機能を足した・変えたときは、関係するカタログの項目と固定ページの記述も一緒に見直します。

## 5. ページのつながり
- 新しいお知らせからは、関係するカタログの項目へリンクします。カタログの項目からは、関係するLPへリンクします。LPからは、詳しい機能のカタログへリンクを返します。
- 新しいLPや固定ページは、ナビに出すページかトップから必ずリンクします。
- 同じ話題のページ同士で、題名と書き出しを使い回しません（`canonical` は各ページ自身なので、ほぼ同じ文のページは評価が割れます）。
- 本文のリンクは `[文字](URL)` の形で書きます。リンクの文字は「こちら」ではなく、行き先の中身にします。

## 6. AIで書き直すとき
- 書き直す前に、1節の表と今の本文を読み、案を利用者に見せます。数・既定値・言い切りは4節で確かめます。
- MCP で書き換えるときは、`*_get` で今の内容を読み、変える所だけを変えます（`*_update` は全部の欄を置き換える）。お知らせの新しい記事は下書きで作り、公開は利用者が確かめてから行います（AIが無断で公開しない）。
- 公開中の記事を直すと、すぐに公開ページが変わります。確認の画面の内容を利用者に見てもらいます。

## 7. 公開の後に確かめること
外から確かめられることは、AIが確かめます。

| 項目 | 確かめ方 |
|---|---|
| 説明文 | ページの `description` が、書き出しの意図した文になっているか（`curl` で読む） |
| サイトマップ | `sitemap.xml` に載っているか。`robots.txt` にサイトマップの場所があるか |
| 検索 | Search Console でサイトを登録し、サイトマップを送る。数日後に、インデックスの状況と検索の語・表示・クリックを見る（運営者が操作する） |
| SNS | 共有した時のカードの題名・説明・画像 |
| 古い記述 | 機能を足した時と、3か月に1回くらい、カタログと固定ページの数・既定値が今と合うかを見直す |

## 8. キットに無いこと
- 構造化データ（よくある質問 等）、ページごとの説明文の欄、検索に載せない指定（404の画面を除く）、お知らせ・カタログの自動のOGPの画像。
- これらが要るときは、計画を書いて承認の境界を確かめます（`minimal-web-kit-design`）。

## 9. 約束しないこと
- 検索の順位、表示やクリックの回数、問い合わせの増加。
- Google が説明文に本文の書き出しを使うこと（検索エンジンが別の文を選ぶことがある）。
