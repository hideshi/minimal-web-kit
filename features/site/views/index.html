3つの約束

AIが書くコードでも崩れないよう、規約と検査で支えます。

MINIMAL DEPENDENCY

組み込む依存は最小限 & 単一バイナリ

Node.js、npm、ビルドツールは一切不要。Go標準機能（net/http, html/template, embed.FS, log/slog）を中心に構成され、CGO不要の単一実行ファイルとしてビルドできます。ブラウザ側のライブラリは、カタログの公開一覧で使う固定版のhtmxだけを同梱しています。

PRIVACY FIRST

個人情報の取得最小化 & 漏洩リスクへの対策

個人情報は既定で取得せず、必要な場合は利用目的・保存項目・保持期間を整理し、保存データの追加前に利用者の承認を得る開発規約を用意しています。保存項目とデータ台帳の突合やログへの機密情報混入を検査する自動テスト、所有者IDによるデータ分離で、漏洩リスクを抑える開発を支えます。

ACCESSIBLE UI

アクセシブルなUIデザイン

外部CSSフレームワークを使わず、単一の自前CSSで完結。JIS X 8341-3 / WCAG 2.1 AA を意識した高コントラスト、明瞭なフォーカスインジケータ、セマンティックなHTMLを採用しています。適合性は、作成したページごとに実画面での検証が必要です。

同梱機能

必要な機能だけをコマンドで有効にできます。有効にしない機能の画面と経路は増えません。

SITE

LPテンプレート

ヘッダー・フッター、検索エンジン向けの設定、sitemapを用意しています。Siteだけなら静的ホスティングにも置けます。

NEWS

お知らせ

公開ページと読み取り専用のJSON API、記事の管理画面です。日時を決めた予約公開もできます。

CATALOG

カタログ

商品や事例の一覧を、キーワード・カテゴリ・タグで絞り込めます。JavaScriptが無くても使えます。

CONTACT

お問い合わせ

IPアドレスを記録せず、外部のCAPTCHAも使わないフォームです。受信箱で、対応の状態とメモを管理できます。

PAGES

固定ページ

会社概要などのページを管理画面で作れます。書き方を絞ったMarkdownで書き、公開の前にプレビューで確かめられます。

AUTH

パスキーの管理者認証

パスワードを使わず、パスキーだけでログインします。管理者・メンバーのロールで、複数人のアカウントを使えます。

FEDERATED AUTH

共通認証（自社システム向け）

管理者認証のアカウントで、自社の別システムにログインできます。止めたアカウントは次の要求から拒否します。他社への開放やSPA・モバイルは対象外です。

BACKUP

バックアップ

稼働中でも、SQLiteの整合した複製を作るコマンドと、複製を検査するコマンドがあります。外への保管は運用で行います。

文書だけでなく、テストで守る

規約を破る変更は、テストが落ちます。安全を保証するものではありませんが、崩れに早く気づけます。

DEPENDENCY

依存の許可リスト

許可していない直接依存と、実行ファイルに入るモジュールの増減を検出します。

DATA

データ台帳との突き合わせ

実際の表と列が、保存目的と保持期間を書いた台帳と合っているかを確かめます。

SPEC

仕様とテストの対応

不変条件とユースケースに、対応するテストがあるかを確かめます。内容の一致はレビューで確かめます。

LOG

ログへの漏洩の検査

入力やトークンがログに出ていないかを、目印の値を流して確かめます。

UI

管理画面の標準と実ブラウザの確認

管理画面が標準の型に沿っているかを検査します。部品の操作はChromeで確かめます。

VULNERABILITY

既知の脆弱性の毎日の点検

Go本体と依存の既知の脆弱性を、CIで毎日調べます。本番へ届けるには配備が要ります。

AI開発ツールと4ステップで構築

編集にはClaude Code、Codex、Cursor、Antigravityのいずれかを推奨します。同梱の6本のスキルを、手順に合わせて読み込みます。

  1. STEP 1

    要件を確かめる

    実装の前に、目的、保存するデータ、増える依存を確かめます。設計スキルが、確認が要る項目を示します。

  2. STEP 2

    同梱機能とGoで作る

    必要な機能をコマンドで組み込み、セマンティックなHTMLとGoで自作の機能を足します。実装スキルが、キットの決まりを示します。

  3. STEP 3

    検査する

    テスト、依存、脆弱性を確かめます。監査スキルと脆弱性のスキルが、見る項目を示します。プライバシーポリシーの見直しにも、専用のスキルがあります。

  4. STEP 4

    本番に出す

    make build で単一の実行ファイルを作って配置します。本番スキルが、手順書の作り方、HTTPSやバックアップで決めること、戻し方を示します。

リポジトリをクローンし、make run で起動できます。

よくある質問（FAQ）

導入前に知っておきたいポイントをまとめました。

JavaScriptやフロントエンドフレームワーク（React / Vue等）は必要ですか？

いいえ、不要です。画面はサーバーサイドレンダリング（SSR）で作り、公開ページはJavaScriptが無効な環境でも閲覧できます。JavaScriptを読み込むのは、パスキーを扱う管理者認証の画面（ログインにはJavaScriptが必要です）、カタログ公開一覧の絞り込み（htmx）、カタログ項目編集のタグ選択の3か所だけで、どれも自サイトから配信するファイルです。

データベースのセットアップや管理は必要ですか？

LPの表示処理はDBにデータを保存せず、新規のセッションCookieも発行しません。ただし、同梱サーバーは起動時にSQLiteのDBファイルを開き、必要なテーブルが無い場合だけ作成します（既存のデータは削除しません）。別のDBサーバーの構築は不要ですが、保存先の権限・容量・バックアップの管理は必要です。

本番はどこに置けますか？

常駐のプロセスとSQLiteのファイルを置けるLinuxサーバー（VPS・EC2等）です。共用レンタルサーバーやサーバーレスの環境には置けません。Siteだけなら静的ホスティングも選べます。HTTPSの終端はリバースプロキシかトンネルで行います。

バックアップは必要ですか？

管理画面を使うなら必要です。データは1つのSQLiteのファイルにあり、サーバーごと失うと戻せません。複製と検査のコマンドはありますが、サーバーの外へ送る仕組みは運用で用意してください。戻せることも、定期的に試してください。

別のシステムのログインに使えますか？

自社が管理するサーバー型のWebアプリなら使えます。OpenID Connectでログインし、要求のたびに認証基盤へ有効性を確かめるので、認証基盤が止まると連携先の保護された機能も使えません。本番での運用実績はまだ無く、実ブラウザの確認はChromiumだけです。

商用利用や独自サービスへの流用は可能ですか？

はい、MIT License のオープンなWebひな形として、商用・個人利用を問わず自由に改変・公開してご利用いただけます。
